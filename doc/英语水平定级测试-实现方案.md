# 英语水平定级测试模块 — 实现方案

> 版本:v1(2026-08-17)· 基准:《句流-完整开发文档-v5-合订版》§6.3「首启定级」
> 目标:把现有的"三问自报熟悉度"升级为一个**真实测量**用户英语水平的定级测试,
> 通过测试评定水平并推荐对应练习等级(入门/初级/中级/中高级/高级/精通)。
> 本方案是 v5 合订版中"自适应 3 句定级"一笔带过条目的完整展开,不构成规范偏差。

---

## 0. 现状与问题

### 0.1 现有首启定级(apps/desktop/src/pages/Onboarding.tsx)

- 六张等级卡(阶段名 + 能做到:can-do)供用户自选;
- 「不确定?帮我测一下」→ **三道自报题**("看到这句你的感觉是?"三选一),
  每题映射到一个等级,取三次选择的中位数写入 `settings.level`。

### 0.2 问题

1. **自报 ≠ 实测**:用户(尤其小白)普遍高估或低估自己,三问自报没有任何
   客观测量成分,定级误差大;定错级直接伤害核心体验(太难→挫败流失,
   太易→无聊流失)。
2. **无结果解释**:测完直接进今日页,用户不知道"为什么是这个级",
   对推荐缺乏信任感。
3. **无重测入口**:定级只在首启出现一次,设置里没有"重新测一下"。
4. **没有利用产品自身的测量能力**:句流的核心机制(看中文/听英文→整句打字)
   本身就是学界验证有效的水平测量手段(见 §1.3),现有定级完全没有用上。

## 1. 方法论依据(网络检索结论)

### 1.1 自适应/多阶段测试(CAT / MST)

- 自适应测试的核心:答对→下一题更难,答错→更容易;停止条件为"置信区间
  足够窄"或"到达题量上限"。自适应定级通常 20–40 题即可达到传统 60–100 题
  固定卷的信度。
- **多阶段测试(MST)**比逐题自适应更工程友好:第一阶段一个**路由模块
  (router)**,按表现把用户路由到第二阶段的不同难度模块(经典 1-2-3 结构)。
  研究表明面向定级的短测验压缩到 ~18 题仍能保持可比信度。
  → 本方案采用 **router + 两个自适应阶段** 的 MST 结构,而非逐题 IRT-CAT
  (无需题目参数标定,离线单机可实现,工程量小一个数量级)。

### 1.2 词汇量快筛(Yes/No 判断,LexTALE 范式)

- 「这是不是一个你认识的英文单词?」式判断测验(真词 + 伪词混合)虽然简单,
  但得分与完整语言能力测验高度相关,被广泛用于分级安置(placement)。
- 计分须用伪词误报率做猜测校正:最简单为 `命中率 − 误报率`(h−f),
  更稳的 cfg 校正 `(h−f)/(1−f)`;高误报率本身是"乱猜"的效度信号。
- 句流已内置 **NGSL 词频表 2827 条(带 band 值)**,与六级词表带
  (500/1000/1500/2000/2800/不设限)天然对齐 —— 按 band 分层抽真词即可
  构造难度阶梯,这是别的产品没有的现成资产。

### 1.3 整句复述/听写作为综合水平测量(Elicited Imitation)

- 「听/看一句话→复述它」(EI)是二语研究公认的**综合水平快捷测量**:
  要正确复述,必须真正理解句子(超出短时记忆容量的句子无法靠死记复现);
  元分析显示 EI 与全面语言测验高相关,且已有**键盘打字版 EI** 的先例。
- 句流的练习机制(整句打字 + 听打)就是打字版 EI。**定级测试的主体阶段
  直接复用 TypingBoard/ReorderBoard 组件**,既是有效测量,又让用户在
  测试中就体验到产品核心玩法(符合 §2.2"冷启动到打出第一个字母 ≤5 秒")。

> 参考来源(检索于 2026-08):
> - EduSynch/BOOKR 关于自适应定级测试设计与停止规则的实践综述
> - Maryland MCAP / ACT RR2012-6 / PMC7003183:MST 路由设计与短测验信度
> - LexTALE(Lemhöfer & Broersma 2012)及 Yes/No 词汇测验计分研究
>   (Zhang, Liu & Ai 2020;Pellicer-Sánchez & Schmitt 2012)
> - Yan et al. 2016 元分析:Elicited Imitation 作为 L2 综合水平测量的效度

## 2. 测试设计(用户视角)

### 2.1 总体结构:三阶段 MST,全程 ≤5 分钟,纯离线零配置

```
入口                Stage A 词汇快筛           Stage B 整句实测            Stage C 语法辨析          结果页
──────              (router,~60s)           (主体,2–3min)             (仅边界不清时,~40s)
选等级卡 ──────┐    24 题 认识/不认识          6–8 句 重组/打字            4–6 题 二选一             推荐等级
              ├──► 真词18(按band分层)  ──► 从路由级起步,           ──► 相邻两级语法点        ──► + 依据解释
「帮我测一下   │    + 伪词6                    答对升/答错降              定向加测                  + 开始练习
 (约3分钟)」──┘    → 路由到低/中/高档                                                            + 手动微调
```

- **Stage A 词汇快筛(router)**:屏幕逐个出现单词,用户按 `←`(不认识)/
  `→`(认识)或点击作答。24 题 ≈ 40–60 秒。
  - 真词 18 个:按 NGSL band 分 6 层(≤300 / ≤600 / ≤1100 / ≤1600 /
    ≤2200 / ≤2800)各 3 个,从词表**确定性抽样**(种子固定,见 §3.4);
  - 伪词 6 个:人工精选、符合英语音系规则的假词(如 *plore, tandle,
    brastic*),用于猜测校正,**不入词表、不做发音**;
  - 计分:每层命中率 × cfg 校正 → 词汇量估计值 `vocab_est`(0–2800+),
    路由:`<400 → 低档(L1 起步)`,`400–1400 → 中档(L2/L3 起步)`,
    `>1400 → 高档(L4 起步)`;
  - **零基础保护**:若 `vocab_est < 150` 且误报率正常,直接出结果推荐
    「入门」,跳过 Stage B/C(避免让完全零基础用户挫败地打不出句子)。
- **Stage B 整句实测(主体)**:复用练习组件做打字版 EI。
  - 从路由档起步,共 6–8 句,**阶梯自适应**:整句一次通过(词级错误 ≤1
    且未看答案)→ 升一级取题;错误 ≥3 或看答案 → 降一级;否则同级再取;
  - 低档(L1/L2)首题用**拆句重组**(键盘数字选词,门槛更低),其余用
    打字板;L5/L6 题用**听打**(隐藏英文,speechSynthesis/piper 朗读)
    以拉开高段区分度;
  - 每题记录:词级正确率(judge 对比)、首键延迟、WPM、是否看答案;
  - 题目为**专用定级题库**(§3.2),不依赖 L4–L6 尚未出厂的内容。
- **Stage C 语法辨析(定向加测)**:仅当 Stage B 结束时能力估计落在两级
  边界(±0.4 级内)才出现。二选一填空,考察相邻两级 `grammar_whitelist`
  的**增量语法点**(如 L2/L3 边界考一般过去时;L4/L5 考现在完成时;
  L5/L6 考虚拟/委婉),4–6 题定向决出边界。
- **结果页**:
  - 大字推荐阶段名(如「中级」)+ 「能做到:点餐、约时间」(can-do);
  - 依据解释(小白能懂的三行):「词汇量约 ~1200 词 · 整句正确率 78% ·
    一般过去时已掌握」;
  - 主 CTA「按这个等级开始练习」→ `setLevel(推荐级)`;
  - 次要入口「自己挑一个等级」→ 回六张等级卡;
  - 不撒花(§6.2:撒花是练习答对的专属仪式)。

### 2.2 入口与重测

| 入口 | 位置 | 行为 |
|---|---|---|
| 首启 | Onboarding 页,替换现有三问自报,文案「不确定?帮我测一下(约 3 分钟)」 | 完成后写 `settings.level` 并进今日页 |
| 重测 | 设置 · 练习与外观 新增行「重新测一下我的水平」 | 完成后提示"推荐从 X 开始",由用户确认是否切换(不静默改级) |
| 报告页提示(二期) | 连续 7 天正确率 >95% 或 <50% 时出现一行安静提示 | 「练习偏易/偏难?重新测一下水平」 |

### 2.3 交互细节(对齐产品现有规范)

- 全程键盘可完成:词汇题 `←/→`,重组数字键,打字直接输入,语法题 `1/2`;
- 顶栏常驻「‹ 退出」与进度条(复用 ProgressBar);中途退出不保存、不惩罚;
- 音效沿用 WebAudioSounds(答对 key/correct,答错 error);
- 测试**不写 SRS、不写练习日志、不消耗试用版每日 5 句额度**(§3.5);
- 全程无 AI 通道依赖(§1.4/§6.3 红线:首启路径绝不出现通道配置);
- 文案零术语:不出现 L1–L6/CEFR/band/WPM,统一走 `levels.ts` 阶段名体系。

## 3. 技术方案

### 3.1 架构分层(遵循现有"纯逻辑下沉 sf-core、数据驱动、双端复用"原则)

```
crates/sf-core/src/placement.rs        纯状态机:出题/计分/路由/停止/结果(显式 now/seed,无 IO)
        │  ▲ 单元测试(#[cfg(test)])
        │  └── crates/sf-wasm         (二期)包一层 JSON ABI,试用站同款测试引流
content/placement/placement.yaml       题库单一事实源:词汇层抽样配置+伪词、定级句、语法题
        │
crates/sf-pipeline (factory)           `sf factory build` 校验题库并打进 content.db(placement 表)
        │
apps/desktop/src-tauri                 新增 3 个 command:placement_bank / placement_save / placement_get
        │
apps/desktop/src/pages/PlacementTest.tsx   流程编排 UI(复用 TypingBoard/ReorderBoard/ProgressBar/levels.ts)
```

### 3.2 题库(content/placement/placement.yaml,新文件)

```yaml
version: 1
vocab:
  # 真词按 band 分层抽样的配置(运行时从 lexicon 表抽,不硬编码词面)
  strata: [300, 600, 1100, 1600, 2200, 2800]
  per_stratum: 3
  exclude: [propn]            # 专有名词不参与
  pseudowords:                # 人工精选 ≥12 个,运行时抽 6
    - plore
    - tandle
    - brastic
    # …符合英语音系,不与真词形近
sentences:                    # 每级 8–10 句,合计 ~50 句;结构同 seed 文件
  - level: L1
    en: "I am a teacher."
    zh: "我是一名老师。"
    words: [...]              # 与 seed 相同的全标注结构
    chunks: [...]
  # … L1..L6,难度由各级词表带 + 句长上限天然保证
grammar:                      # 相邻级边界题,每个边界 4–6 题
  - boundary: [L2, L3]        # 考 L3 增量语法:past_simple
    prompt_zh: "我昨天看了一部电影。"
    stem: "I ___ a movie yesterday."
    options: ["watch", "watched"]
    answer: 1
  # … [L1,L2] [L3,L4] [L4,L5] [L5,L6]
```

要点:

- **定级句独立成库**,不依赖出厂句库(L4–L6 出厂句目前为 0,见开发状态
  待完成项);每句用现有 `Validator` 按对应级 spec 校验(词表带/句长/成分
  覆盖),保证难度阶梯真实成立 —— 这一步在 `sf factory build` 中强制执行,
  校验不过则构建失败;
- 伪词构建期校验:**必须不在词表中**、长度 4–8、无重复;
- 真词运行时从 `lemma` 表按层抽样(而非写死),词表升级自动受益;
- content.db 新增表:
  `placement_sentence(id, level, …与 sentence 同构)`、
  `placement_grammar(id, lo_level, hi_level, prompt_zh, stem, options, answer)`、
  `meta` 增加 `placement_rev`;伪词与抽样配置存 `meta`(JSON)。

### 3.3 sf-core 新模块 `placement.rs`(纯逻辑,~400 行 + 测试)

```rust
/// 题库(由宿主从 content.db 装配后传入,sf-core 不做 IO)
pub struct PlacementBank {
    pub vocab_real: Vec<VocabItem>,      // {word, band}
    pub vocab_pseudo: Vec<String>,
    pub sentences: BTreeMap<LevelId, Vec<Sentence>>,
    pub grammar: Vec<GrammarItem>,       // {lo, hi, prompt_zh, stem, options, answer}
}

pub enum PlacementStage { Vocab, Sentence, Grammar, Done }

pub enum PlacementItem {                 // next_item() 的产出
    Vocab { word: String },              // 伪词与真词同形出题
    Sentence { sentence: Sentence, mode: Mode },  // reorder/typing/listening
    Grammar { prompt_zh: String, stem: String, options: [String; 2] },
}

pub enum PlacementAnswer {
    VocabKnown(bool),
    SentenceResult { word_errors: u32, seen_answer: bool, dur_ms: u32, wpm: f32 },
    GrammarChoice(u8),
}

pub struct PlacementTest { /* seed, bank 引用序号, 阶段状态, 作答记录 */ }

impl PlacementTest {
    pub fn new(bank: &PlacementBank, seed: u64) -> Self;   // SplitMix64 抽样/洗牌
    pub fn next_item(&mut self) -> Option<PlacementItem>;  // None = 测试结束
    pub fn submit(&mut self, answer: PlacementAnswer);
    pub fn progress(&self) -> f32;                         // 0..1,驱动进度条
    pub fn result(&self) -> Option<PlacementResult>;       // Done 后可取
}

pub struct PlacementResult {
    pub level: LevelId,            // 推荐等级
    pub vocab_est: u32,            // 词汇量估计(cfg 校正后)
    pub sentence_accuracy: f32,    // 整句词级正确率
    pub false_alarm_rate: f32,     // 伪词误报率(效度指标,>0.5 标记低信度)
    pub low_confidence: bool,
    pub grammar_notes: Vec<String>,// 「一般过去时已掌握」等结果页解释素材
    pub taken_at: i64,
}
```

**计分与路由算法**(全部整数/浮点算术,无需 IRT 标定):

1. 词汇:逐层命中率 `h_i`,总误报率 `f`;层估计
   `vocab_est = Σ 层宽_i × max(0, (h_i − f) / (1 − f))`(cfg);
   路由:`<400→低档` `400–1400→中档` `>1400→高档`;`<150→直接出结果 L1`;
   `f > 0.5` 置 `low_confidence`(结果页文案改为"建议从 X 试试")。
2. 整句:能力值 `θ` 初始 = 路由档中位级(1.0–6.0 连续值);
   每题 `θ += 0.5 × 方向`(通过升/失败降,同级 ±0),题目取
   `round(θ)` 级;词级错误率与看答案共同决定方向(阈值见 §2.1);
   连续两题同向后步长减半(0.5→0.25,阶梯收敛);8 题或步长收敛后停。
3. 语法:若 `|θ − round(θ)| > 0.4` 或最后两题一升一降,取边界
   `[floor(θ), ceil(θ)]` 的语法题 4 题,≥3 对取高级,否则低级。
4. 推荐 = 收敛后的 `round(θ)`,再做**保守修正**:`low_confidence` 或
   词汇估计与 θ 相差 ≥2 级时,向下取一级(宁可偏易 —— 偏易的代价是
   无聊几天,偏难的代价是流失)。

**单元测试**(与现有 sf-core 测试风格一致):全对→精通、全错→入门、
乱按(伪词全"认识")→低信度、边界震荡→触发语法加测、同 seed 结果
可复现、L1 直通道触发条件、每题 progress 单调递增等,≥12 个用例。

### 3.4 确定性与防背题

- `PlacementTest::new(bank, seed)`:首启用 `now_unix()` 作 seed(每人不同);
  重测用新 seed → 抽到不同词/句,降低背题效应;
- 同 seed 全程可复现(与 build_session 的确定性契约一致,便于测试与回归)。

### 3.5 桌面端接线(新增 3 个 Tauri command)

```rust

placement_get(state) -> Option<PlacementResult> // kv_get,供设置页/报告页展示上次结果
```

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 定级句难度阶梯不真实(题目质量) | 构建期用现有 Validator 按级 spec 强校验;词汇层直接锚定 NGSL band,难度客观 |
| 用户乱按导致误级 | 伪词误报率作效度闸门 → 低信度文案 + 保守降级推荐;结果页永远提供手动改级出口 |
| 高估/低估仍然发生 | 推荐取保守侧;等级随时可在今日/内容库/设置切换(现有能力);二期报告页"建议重测"闭环 |
| 首启时长超 §6.3 的 60 秒预期 | 等级卡自选仍是默认快路径(≤60s 不变);测试是显式可选项且标注"约 3 分钟";零基础 90 秒内直通结果 |
| 听打依赖 TTS,piper 语音包未随包 | Stage B 听打题仅在 speechSynthesis 可用时启用,不可用则自动换成打字题(能力估计公式不变) |
| L4–L6 无出厂句,测完没得练 | 定级句自带,测试不受影响;结果页对 L4–L6 推荐附一行"该等级出厂句库即将上线,可先在生成工坊按场景生成"(诚实呈现,联动待办#1"5000 句全量生产") |

## 6. 规范符合性检查

- §1.4/§6.3:全程离线、零配置、无 AI 通道露出 ✓(词汇/语法题本地题库,
  整句判分走本地 judge)
- §2.2 冷启动 ≤5 秒打出第一个字母:等级卡快路径不变;测试属可选深入 ✓
