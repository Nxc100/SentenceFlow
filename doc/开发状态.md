## 0a. 2026-08-18 opencode 一键安装(小白友好,替代命令行引导)

- **背景**:设置页此前展示 `curl … | bash`(Unix 命令),Windows 小白
  在 cmd 里必然失败(真机报错截图);且官方无 install.ps1。
- **方案(免 Node/免终端,优于"先装 Node 再跑命令")**:opencode 官方
  把各平台二进制发布为 npm 平台包(`opencode-windows-x64`,tgz 内含单个
  `bin/opencode.exe`,实测 57MB/npmmirror 约 2 分钟)。新增
  `installer.rs`:registry 候选(npmmirror 优先,`channels.json
  npm_registries` 数据驱动,rev 3)→ 解析最新版(联动 opencode_known_bad
  红线)→ 流式下载(`install://progress` 事件,遵循 AI 代理设置)→
  解出 exe 至 `<app-data>/tools/opencode/` → `--version` 健康检查 →
  写 `settings.ai.opencode_bin`(探测/生成/答疑经 bin_override 即刻生效);
  同版本重装短路。
- **登录也一键化**:`opencode_login` 以 CREATE_NEW_CONSOLE 直接弹出
  独立控制台运行 `auth login`,小白按提示方向键+回车即可,无需会打命令。
- **W2 结论修正(2026-08-18 实证,用户手测质疑触发)**:隔离 auth 的
  全新环境下 `opencode models` 照常列出 8 个 `opencode/` 免费模型,且
  `opencode run` 真实生成成功——**Zen 免费层匿名可用,登录不是必经步骤**。
  探测的 NotAuthed(名单为空)语义改释为"网络波动/名单下线",UI 改为
  「重新检测为主 + 备用登录」;安装完成即就绪,小白全程零命令零登录。
- **UI**:opencode 通道卡 not_installed → 「一键安装 opencode(约 60MB)」
  + 实时进度条/阶段文案 + 失败红字,手动命令(npm i -g)收进「高级」
  折叠;not_authed → 「打开登录窗口」+ 白话指引。
- **老系统兼容(真机踩坑,老 Win10 报"无法定位程序输入点
  ClosePseudoConsole")**:opencode 是 Bun 构建,硬性要求 Win10 1809+
  的 ConPTY API。三层防护:①安装前 RtlGetVersion 预检 build <17763
  直接白话拒绝并推荐 Zen 直连(不浪费下载);②应用启动即 SetErrorMode,
  子进程继承后系统不再弹加载器对话框,坏二进制统一走中文错误
  (0xC0000139/0xC000007B 识别为系统过旧);③自检失败清理残件。
- **探测超时放宽(真机踩坑 + 有意规范偏差)**:VMware 慢磁盘虚拟机上
  一键安装后探测报"网络不稳定,已停表"——根因不是网络:§11.C 规定探测
  超时 3s,但 opencode 是 ~179MB Bun 单文件,慢盘冷启动 3–10s,
  `--version` 超时被映射成通用网络文案。改为分级超时(--version 20s /
  models 45s,仍全程只读),version 超时给专属文案「opencode 启动较慢
  ——稍等再点重新检测」。
- **全局安装(用户需求:兼容小白与有经验用户)**:安装目录从应用数据目录
  改为标准用户级位置 `%LOCALAPPDATA%\Programs\opencode\`(恰在探测器
  兜底搜索列表内),装完经隐藏 PowerShell 以
  `[Environment]::SetEnvironmentVariable('Path',…,'User')` 追加用户
  PATH(读改写原子 + 自动广播 WM_SETTINGCHANGE,新开终端直接可用
  `opencode` 命令;免管理员、不动系统 PATH、幂等);PATH 写入失败不致命
  (应用自身走 opencode_bin)。旧应用数据目录副本自动迁移清理。

### 网络与答案显示修订(同日第三轮,打包 exe 实测)

- **AI 代理设置**(直连网络访问境外端点):设置 · AI 接入新增"网络"区,
  可填本机代理客户端 HTTP 端口(如 `http://127.0.0.1:7897`),仅 AI 请求
  走代理 —— opencode 子进程经 HTTP(S)_PROXY 环境变量注入(Bun fetch 遵守,

## 二、与规范的有意偏差(均为实现取舍,已在代码注释中就地记录)

1. **token 预估不用 tiktoken-rs**(§7.5)——四通道没有一家按 tiktoken 词表计费,
   精确的 tiktoken 数一样是错的;改用字符类启发式(刻意偏高保守),
   实际用量以 API usage 回填为准,UI 恒标"以官方账单为准"。`sf-llm/src/estimate.rs`
2. **simhash 阈值 16、bigram 权重 1**(§7.4)——按种子句库实测标定:
   真近重复 6–16,不同短句最低 17;宁漏勿错杀(漏网靠抽审)。`sf-pipeline/src/simhash.rs`
3. **content.db 无 note_tpl/note_slots 表**(§7.7)——note 模板化是工厂侧省
   token 手段,库内保留反范式 `note` 单列,模板层留在 prompt 侧。`sf-pipeline/src/store.rs`
4. **progress.db 新增 `favorite` 表**(§7.7 未列)——收藏(§4.3)需要落地处;
   错题本仍按规范由 `srs` 派生。`apps/desktop/src-tauri/src/progress.rs`
5. **opencode 只用 standalone `run`,不用 serve/attach**(§3.4)——真机 spike
   证实 1.18.18 的 `run --attach` 对带密码 serve 只回吐 step_start、不转发
   text 事件,serve 优先策略在当前 CLI 面上不可实现;按 §10 逃生门取文档
   规定的降级路径(每微批冷启动 ~1-2s)。重返 serve 需走官方
   `@opencode-ai/sdk` 会话 API。
6. **周报 PDF = 打印样式 + 系统"另存为 PDF"**(§4.5)——避免引入 PDF 生成
   依赖;报告页带 `@media print` 版式。
7. **词表带用 HashMap 而非 fst**(§7.4"NGSL fst")——2800 词条规模下 fst
   无收益;查询接口不变,后续可无痛替换。
8. **重组通过后进入解析视图无独立"mini 签名时刻"**——重组定位为入口玩法,
   直接衔接打字二遍流;撒花仍为打字答对专属。

## 三、W2 真机 spike 结论(opencode 1.18.18,Windows,2026-08-16)

- `opencode run -m <model> --format json`:每行一个 JSON 事件——
  `{"type":"step_start"…}` / `{"type":"text","part":{"text":"…"}}` /
  `{"type":"step_finish",…,"tokens":{…},"cost":0}`;prompt 经 stdin 正常;
  沙箱 cwd + 我方 `opencode.json`(agent.sf-gen.permission 全 deny 键形)不报错。
- `opencode serve --port 0` **落在默认端口 4096 而非随机端口**;URL 打到
  stdout:"opencode server listening on http://127.0.0.1:4096"。
- `run --attach`:无密码报 "Session not found";带同密码环境变量能连上,
  但只转发 step_start、**text 事件不回吐** → attach 不可用作补全传输,已从
  适配器移除(见偏差 5)。
- npm 全局安装形态为 `opencode.cmd`,tokio spawn 直接可用(探测与 run 均验证)。
- 免费模型名单(时点):big-pickle、deepseek-v4-flash-free、hy3-free、
  laguna-s-2.1-free、mimo-v2.5-free、nemotron-3-ultra-free、
  nemotron-3.5-lightning-free。deepseek-v4-flash-free 的 JSON 纪律:
  两轮 10 句批全部可解析(破碎数据 0)。
