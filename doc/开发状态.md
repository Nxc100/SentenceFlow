## 0. 2026-08-20 发行形态改为**免费版**(FREE_EDITION)

产品决策:不再收费,软件包免费分发给所有人,装上即全功能。

- **一个常量决定形态**(`licensing.rs`):`FREE_EDITION: bool = true`。
  `current_state()` 短路返回新增的 `LicenseState::Free`,**不读 license.sflic、
  不碰试用锚点**(连带好处:不再弹系统钥匙串授权框)。
- **下游闸口自然失效,零散改动**:`submit_attempt` 的每日 5 句上限只在
  `LicenseState::Lapsed` 分支生效 → 永不触发;顶栏胶囊只为 trial/lapsed 渲染
  → 不出现;`trial_limit` 错误码的前端处理成为不可达的死路径(保留,无害)。
- **买断制实现原样保留**:`crates/sf-license`(验签 + 试用状态机 + 签发 CLI)、
  `activate_license`/`export_license` 命令、Settings 激活卡全部不动;
  `FREE_EDITION` 改回 `false` 重新打包即恢复。这样做而不是删掉,是因为删除是
  不可逆的,而一个常量的可逆性成本几乎为零。
- **设置 · 授权页**新增免费版分支:「免费版 · 全部功能已解锁,无需激活、
  无使用期限」,不再显示粘贴激活框。
- **公钥泄漏问题降级为非阻塞**:`LICENSE_PUBLIC_KEY_B64` 的配对私钥
  `tools/dev-keys/dev-signing-key.b64` 曾**被 git 跟踪并推送到公开仓库**
  (`.gitignore` 只挡 `*.secret`,dev key 叫 `.b64` 正好绕过)。
  **本次已 `git rm` 整个 `tools/dev-keys/`**,并把 `.gitignore` 加固为
  后缀 + 文件名双保险(`*signing-key*` / `*.b64` / `tools/dev-keys/`)。
  历史里的那份不做 rewrite —— 它只对"内嵌 dev 公钥的构建"有效,而免费版
  根本不走验签;但**日后若改回收费,必须先生成全新密钥对**,否则任何人
  翻 git 历史就能拿旧私钥自签终身许可证。已在 README、功能全景文档、
  构建与发布手册、手动测试指引、代码注释五处就地记录。
- **验证**:`cargo test --workspace --all-features` 209 用例全绿;
  `npm run typecheck` 通过;`cargo clippy -p sentenceflow-desktop` 无新增告警
  (仅剩既有的 `chat_message_add_full` 参数过多)。
- **已发布 v0.2.0**(2026-08-20):版本号 0.1.0 → 0.2.0(Cargo.toml workspace +

## 0. 2026-08-20 宽屏自适应(最大化窗口不再大片留白)

用户反馈:窗口最大化后内容锁在中间一条窄柱子里,两侧各空约 380px。
根因是 `.page { max-width: 1080px }` 一刀切,与内容类型无关。

- **布局令牌化**(`packages/ui/src/tokens.css`,与其它设计令牌同处):
  `--sf-page-max: 1600px`(列表/看板类)、`--sf-page-max-narrow: 1120px`
  (表单/阅读类:设置、我的水平 —— 再宽只会把标签和控件拉到两端)、
  `--sf-page-pad: clamp(20px, 2.4vw, 48px)`(留白随视口伸缩)、
  `--sf-read-max`(长文本可读宽度)。页面不再各自硬编码宽度。
- **短内容改多列而不是拉长条**:我的句库、AI 造句生成结果、报告的薄弱分析
  都从「一行一条横贯整页」改成 `auto-fill minmax(440px, 1fr)` 栅格 ——
  1920 下 3 列,一屏看完 20 句;句库展开解析的那条 `grid-column: 1/-1`
  独占整行(成分卡需要宽度)。
- **图表真正自适应**:WPM/正确率曲线由固定 560px 改 viewBox 拉伸铺满
  (`vector-effect: non-scaling-stroke` 保线宽);练习热力图按可用宽度
  决定周数(ResizeObserver,12–53 周),最大化后直接看满一年。
- **聊天页**:面板铺满页宽,对话本身收在 920px 列里居中(消息、输入框、
  附加技能条共用同一列宽,视觉对齐),宽屏下气泡不会拉成一行到底。
- **实测**(打包 exe,1920×1009 与 1008×681 两档):八个页面两侧留白从
  378px 降到 118px(窄档页面居中对称);窄窗口零横向溢出、无横向滚动条。
  练习/情景练习全屏页维持"专注式居中"(此前对齐参照原型打磨过的设计),
  未改动。

### 全量 UI 走查修复(同日,用户视角逐路径测试)

   **「一次打对(无错字且未看答案)的句子占比」**,可解释且不被重打
   影响;等级练习完成页同步统一口径。

   「正在停止(等这一批请求返回)…」。
7. **停止后文案误导**:0 句产出仍提示「去「场景」页开练」→ 收尾文案

  说明并建议提高等级/换场景说法。补足批断点续跑同样成立(带测试)。
- **失败样本回灌(运行时形态,§8)**:任务内被 OverLevel/UnknownWord 拒绝的

## 二、与规范的有意偏差(均为实现取舍,已在代码注释中就地记录)

1. **token 预估不用 tiktoken-rs**(§7.5)——四通道没有一家按 tiktoken 词表计费,
   精确的 tiktoken 数一样是错的;改用字符类启发式(刻意偏高保守),
   实际用量以 API usage 回填为准,UI 恒标"以官方账单为准"。`sf-llm/src/estimate.rs`
2. **simhash 阈值 16、bigram 权重 1**(§7.4)——按种子句库实测标定:
   真近重复 6–16,不同短句最低 17;宁漏勿错杀(漏网靠抽审)。`sf-pipeline/src/simhash.rs`
3. **content.db 无 note_tpl/note_slots 表**(§7.7)——note 模板化是工厂侧省
   token 手段,库内保留反范式 `note` 单列,模板层留在 prompt 侧。`sf-pipeline/src/store.rs`
4. **progress.db 新增 `favorite` 表**(§7.7 未列)——收藏(§4.3)需要落地处;
   错题本仍按规范由 `srs` 派生。`apps/desktop/src-tauri/src/progress.rs`
5. **opencode 只用 standalone `run`,不用 serve/attach**(§3.4)——真机 spike
   证实 1.18.18 的 `run --attach` 对带密码 serve 只回吐 step_start、不转发
   text 事件,serve 优先策略在当前 CLI 面上不可实现;按 §10 逃生门取文档
   规定的降级路径(每微批冷启动 ~1-2s)。重返 serve 需走官方
   `@opencode-ai/sdk` 会话 API。
6. **周报 PDF = 打印样式 + 系统"另存为 PDF"**(§4.5)——避免引入 PDF 生成
   依赖;报告页带 `@media print` 版式。
7. **词表带用 HashMap 而非 fst**(§7.4"NGSL fst")——2800 词条规模下 fst
   无收益;查询接口不变,后续可无痛替换。
8. **重组通过后进入解析视图无独立"mini 签名时刻"**——重组定位为入口玩法,
   直接衔接打字二遍流;撒花仍为打字答对专属。

## 三、W2 真机 spike 结论(opencode 1.18.18,Windows,2026-08-16)
