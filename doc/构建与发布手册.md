# 句流 SentenceFlow — 构建与发布手册

> 目标:在**没有 AI 助手**的情况下,你自己改完代码/内容后,能照本手册
> 从零完成编译、测试、打包、部署、发布的全流程。
> 所有命令均在 **PowerShell** 中、于**仓库根目录** `D:\xc_work\xc_english\SentenceFlow` 执行(除非另注明)。
> 更新时间:2026-08-18。

## 1. 环境要求(一次性准备)

| 依赖 | 版本 | 用途 | 验证命令 |
|---|---|---|---|
| Rust(rustup) | 1.85+(edition 2024) | 全部后端 crate | `cargo --version` |
| Node.js + npm | Node 18+ | 前端 monorepo | `node --version` |
| wasm32 target | — | 试用站 wasm | `rustup target add wasm32-unknown-unknown` |
| wasm-pack | 最新 | 构建 sf-wasm | `wasm-pack --version`(缺则 `cargo install wasm-pack`) |
| WebView2 Runtime | 系统自带(Win11) | 桌面端渲染 | 一般无需操作 |

首次克隆仓库后执行一次:

```powershell
npm install          # 安装全部 npm workspace 依赖
```

> NSIS 打包器**不需要**单独安装,Tauri 构建时自动下载。

## 2. 项目结构速览(改哪里 → 需要跑什么)

| 目录 | 内容 | 改动后需要 |
|---|---|---|
| `crates/sf-core` | 纯逻辑(判分/SRS/会话/统计/定级) | §3 测试 → §5 打包 |
| `crates/sf-pipeline` | 生成校验管线 + `sf` 工厂 CLI | §3 测试(+§4 若动了校验规则) |
| `crates/sf-llm` | 4 个 AI 通道适配器/策略 | §3 测试 → §5 打包 |
| `crates/sf-wasm` | 试用站 wasm ABI | `npm run build:wasm` |
| `apps/desktop/src-tauri` | Tauri 后端(commands 等) | §3 → §5 |
| `apps/desktop/src` | 桌面前端页面 | `npm run typecheck` → §5 |
| `packages/ui` | 双端共享组件/音效/等级文案 | `npm run typecheck` → §5(试用站也受影响) |
| `apps/web-trial` | 在线试用站 | `npm run build:trial` |
| `content/specs\|seed\|placement\|lexicon` | 等级规格/种子句/定级题库/词表 | §4 内容构建 → §5 |
| `content/channels.json` | 通道策略(改动记得 rev+1) | §4 → §5(资源文件) |

**类型三处同步铁律**:Rust 里改了 serde 结构(如 Settings、ModelInfo、
PlacementResult),必须同步改 `apps/desktop/src/ipc.ts` 的 TS 镜像;
若 sf-core 类型且试用站可达,还要看 `packages/ui/src/types.ts` 与 `sf-wasm`。

## 4. 内容构建(改了 content/ 下任何东西后)

```powershell
# 校验种子句 + 定级题库(不写文件,只报错)
cargo run -p sf-pipeline --features factory --bin sf -- factory validate

# 正式构建 content.db(校验不过会直接失败)
cargo run -p sf-pipeline --features factory --bin sf -- factory build

# 金标回归(改了校验器/prompt 之后跑)
cargo run -p sf-pipeline --features factory --bin sf -- gold run

# 重新导出试用站内容(改了 L1/L2 种子句后)
cargo run -p sf-pipeline --features factory --bin sf -- export trial
```

产物:`content/build/content.db`(gitignored,打包时作为资源被带走)。

### 4.1 新增一个出厂场景包(内容生产流水线)

```powershell
# ① 在软件里用「生成工坊 → 场景对话」生成一段对话(如"和房东谈续租")
# ② 导出为出厂 YAML 素材(全标注)
cargo run -p sf-pipeline --features factory --bin sf -- export scenario `
  --db "$env:APPDATA\app.sentenceflow.desktop\user_content.db" `
  --pack "和房东谈续租" --out content\scenario\rent-renewal.yaml `
  --id rent-renewal --category "生活" --intro "续租谈价与合同细节。" --reference-level L3
# ③ 人工审校(必做):打开 YAML 重排话轮、修正 speaker A/B、删掉不连贯的句子
#    —— 生成结果里需要修补的句子会落到末尾,顺序必然要人工整理
# ④ 校验 + 打包
cargo run -p sf-pipeline --features factory --bin sf -- factory validate
cargo run -p sf-pipeline --features factory --bin sf -- factory build
```

场景包红线(校验会拦):每包 ≥6 轮、`speaker` 只能是 A/B、包 id 唯一、
包内不得有近重复句;**词表不设限**(场景对话取材真实生活,latte/deposit
这类词表外词是正常的),但结构/成分覆盖/音标照旧强校验。

常见校验失败与对策:
- **「超出当前等级的常用词范围」**:该词的 NGSL band 超过等级词表带
  (L1≤500 / L2≤1000 / L3≤1500 / L4≤2000 / L5≤2800 / L6 不限)→ 换更常用的词;
- **「不在常用词表内」**:词不在 `content/lexicon/base.tsv` 的 2827 词中
  (专有名词标 `pos: propn` 可豁免);
- **「与已有句子重复」**:simhash 近重(阈值 16),短句极易撞 → 把句子改
  得更有区分度(换主语/加状语);
- 定级题库额外红线:每级 ≥6 句、每个相邻边界 ≥4 道语法题、伪词不得是
  词表内真词。

## 5. 桌面端发布构建(核心流程)

```powershell
# ① 杀掉可能占用 exe 的进程(否则链接期报「拒绝访问 os error 5」)
taskkill /IM SentenceFlow.exe /F 2>$null
taskkill /IM sentenceflow-desktop.exe /F 2>$null
taskkill /IM msedgewebview2.exe /F 2>$null

# ② 构建(约 2–10 分钟;内含前端 vite build + Rust release 编译 + NSIS 打包)
Set-Location apps\desktop
npx tauri build --bundles nsis
Set-Location ..\..
```

产物:

| 文件 | 说明 |
|---|---|
| `target\release\sentenceflow-desktop.exe` | 裸程序(**不自包含**,见 §6) |
| `target\release\bundle\nsis\SentenceFlow_0.1.0_x64-setup.exe` | 给用户的安装包(自带资源 + WebView2 引导) |

**改了图标(icons/*.ico)后必须强制重链接**,否则 exe 内嵌图标不变:

```powershell
cargo clean -p sentenceflow-desktop --release
# 然后重跑上面的 ② 
```

> 看到旧图标先别怀疑构建——多半是资源管理器缓存:
> `ie4uinit.exe -show`,不行就删 `%LOCALAPPDATA%\IconCache.db` 与
> `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db` 后重启资源管理器。

### 5.1 发布产物到 GitHub Releases

> 完整说明(gh 是什么、新机器怎么装、踩过的坑、命令速查)见
> **《发布到 GitHub-Releases 指南》** `doc/发布到GitHub-Releases指南.md`。
> 这里只列日常命令。

**二进制不进 git 历史**(exe 16MB + 安装包 5MB 无法增量压缩,入库会让仓库
按提交次数线性膨胀且不可回收)。发布走 GitHub Releases:

```powershell
# ① 把成品收进本地暂存区 release/(该目录已 gitignore)
New-Item -ItemType Directory -Force release | Out-Null
Copy-Item target\release\sentenceflow-desktop.exe release\SentenceFlow.exe -Force
Copy-Item target\release\bundle\nsis\SentenceFlow_0.1.0_x64-setup.exe release\ -Force
Copy-Item content\build\content.db  release\content.db  -Force
Copy-Item content\channels.json     release\channels.json -Force

# ② 发布新版本(gh 已安装于 C:\Program Files\GitHub CLI\gh.exe)
$gh = "C:\Program Files\GitHub CLI\gh.exe"
& $gh release create v0.1.1 release\*.exe release\content.db release\channels.json `
  --title "句流 SentenceFlow v0.1.1" --notes "本版改动…"

# ③ 或者:覆盖已有版本的附件(日常刷新最新构建)
& $gh release upload v0.1.0 release\*.exe --clobber
```

发布页:<https://github.com/Nxc100/SentenceFlow/releases> —— 用户在仓库首页
右侧「Releases」一键下载,不需要懂 git。

发版前记得同步 `tauri.conf.json` 的 `version` 与安装包文件名、tag 号。

> gh 首次使用需 `gh auth login --hostname github.com --git-protocol https --web`
> (浏览器授权一次,凭据存系统钥匙串)。

## 6. 部署绿色版 dist-portable(本机手动测试用)

**单拷 exe 必闪退**——它依赖旁边的资源文件。绿色版 = 三件套:

```powershell
Copy-Item target\release\sentenceflow-desktop.exe dist-portable\SentenceFlow\SentenceFlow.exe -Force
```

绿色版必须整个文件夹一起拷,且目标机需已有 WebView2。

## 11. 踩坑速查表

| 症状 | 原因 | 对策 |
|---|---|---|
| 构建报「failed to remove …exe 拒绝访问 (os error 5)」 | exe 被运行中的进程占用 | §5 ① 的三条 taskkill 后重试 |
| 拷出去的 exe 闪退 | 单 exe 不自包含 | §6 三件套 / 用安装包 |
| 换了 .ico 但 exe 图标没变 | 资源未重链接 | `cargo clean -p sentenceflow-desktop --release` 再打包 |
| 文件图标看着还是旧的 | Explorer 图标缓存 | §5 末尾的缓存清理 |
| 改了 channels.json 不生效 | 三级回退:app-data 副本 > 随包资源 > 内置 | 删 `%APPDATA%\app.sentenceflow.desktop\channels.json` 或一并更新 |
| `git commit -m` 报 pathspec 错误 | 消息含英文双引号触发 PS 5.1 转义缺陷 | 改用中文引号「」 |
| CI rust job 报 content.db 不存在 | 它是 gitignored 构建产物 | CI 已配置先跑 factory build;本地同理 |
| opencode 探测报启动慢/超时 | 179MB Bun 单文件慢盘冷启动 | 正常,稍候重新检测(超时已放宽 20s/45s) |
| 老 Win10 装 opencode 报 ClosePseudoConsole | 系统 < Win10 1809 | 无解,引导用户走 Zen 直连 |
| serde 结构改了前端报错/数据错位 | 忘了同步 ipc.ts / types.ts 镜像 | 见 §2 三处同步铁律 |

## 12. 正式对外发版前的额外清单

- [ ] **确认发行形态**:`apps/desktop/src-tauri/src/licensing.rs` 的
  `FREE_EDITION` 当前为 `true`(免费版:装上即全功能,无激活/无试用期/
  无每日上限)。保持免费则此项无须处理。
- [ ] **仅当改回买断制(`FREE_EDITION = false`)时**:必须先
  `sf-license keygen` 生成全新密钥对、把公钥换进 `LICENSE_PUBLIC_KEY_B64`、
  私钥离线保管。现有那把是**已作废的开发公钥**,配对私钥曾入过仓库
  (文件已删,但留在 git 历史里,视为已泄漏)。
- [ ] `tauri.conf.json` 的 `version` 与安装包文件名同步递增。
- [ ] `content/channels.json` 的 `rev` 递增、`prices_updated_at` 刷新。
- [ ] 跑一遍 §3 + §4 + §5,在干净虚拟机上装一次安装包做冒烟测试
  (首启定级 → 练一句 → 一键装 opencode → 生成 3 句)。
- [ ] `doc/开发状态.md` 记录版本变更要点。
