# 场景练习模块(不分等级)— 实现方案

> 版本:v1(2026-08-18)· 性质:**v5 合订版之外的新增模块**(合订版无此设计,
> 本方案自带设计依据,落地后在 doc/开发状态.md 记录)。
> 目标:①新增「场景练习」——围绕真实生活场景的**对话式整句练习**,不受
> 六级词表带限制;②生成工坊支持「场景对话模式」,按真实对话需求生成
> (不分等级)。

---

## 1. 调研结论(方法论依据)

1. **情景对话练习有效性**:二语研究与近年 LLM 教学系统的共识——从
   具体、实用的交际场景切入,在目标导向的模拟对话中练习,对口语流利度
   提升显著;任务型对话系统实验组的口语流利度显著优于对照组。
2. **功能-意念大纲(Functional-Notional Syllabus)**:场景分类不按语法
   难度组织,而按**交际功能**(请求/道歉/点单/砍价/投诉)与**生存主题**
   (Nation & Crabbe 的旅行生存大纲)组织——这正是"不分等级"的教学法
   正当性:生存表达无所谓难度阶梯,要什么学什么。
3. **语块/公式化序列(Formulaic Sequences)**:母语者口语 55–80% 由
   预制语块构成;整句/整块记忆-提取显著优于逐词组装,是流利度的核心
   机制。**整句打字练习恰好是语块内化的理想载体**——场景句应优先选取
   高频公式化表达("Could I get…", "I'm just looking, thanks."),
   而非语法示范句。

> 来源:[LLM 情景对话系统(arXiv 2403.20005)](https://arxiv.org/abs/2403.20005) ·
> [任务型对话系统教学实验(ERIC EJ1277007)](https://eric.ed.gov/?id=EJ1277007) ·
> [生存语言大纲(Nation & Crabbe)](https://www.researchgate.net/publication/28178443_Survival_Language_Learning_Syllabuses_Revisited_A_Customized_Functional-notional_Approach) ·
> [语块与口语流利度(Frontiers 2022)](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2022.949675/full) ·
> [显式语块教学提升口语流利度(ScienceDirect)](https://www.sciencedirect.com/science/article/abs/pii/S0024384121000449)

## 2. 产品设计

### 2.1 心智模型:场景包(ScenePack)= 一段真实对话

- 一个场景包 = 一段**有序、双角色**的真实对话(8–16 轮),如「咖啡店点单」:
  A 店员 / B 顾客,句子按对话顺序排列,语言优先取高频语块。
- 与等级练习的关系:**平行入口,互不干扰**——场景句不进入六级每日
  SRS 队列(防污染,见 §3.2),等级练习照旧;场景练习是"要用什么练什么"
  的速成通道。
- 每句可 ⭐ 收藏(已有能力),收藏后可在内容库一键重练。

### 2.2 场景分类体系(功能-意念大纲落地,预置 12 包起步)

| 分类 | 出厂场景包(首批) |
|---|---|
| 餐饮 | 咖啡店点单 · 餐厅点餐与结账 |
| 出行 | 机场值机与安检 · 酒店入住退房 · 打车与问路 |
| 购物 | 超市与结账 · 退换货 |
| 医疗 | 药店买药 · 医院挂号问诊 |
| 社交 | 初次见面寒暄 · 邀约与婉拒 |
| 工作 | 求职面试常见问答 |

分类与包全部数据驱动(内容文件,§3.3),后续扩包零代码。

### 2.3 用户流程

```
左侧栏「场景」💬
  → 分类分组的场景包卡片(名称 + 一句话简介 + 句数 + 已练标记)
    → 包详情:对话预览(A/B 气泡,中文摘要)+ [开始练习]
      → 对话式练习(§2.4)
        → 完成页(整段对话回放 + 句数/正确率/用时)
```

生成工坊顶部新增模式切换:**「按等级生成 | 场景对话(不分等级)」**。
场景对话模式下隐藏等级选择,输入场景描述(如「和房东谈续租」)→ 生成
一段真实对话,通过后自动成为「我的场景包」,出现在场景页「我的」分组。

### 2.4 对话式练习(与等级练习的三点差异)

1. **不洗牌**:按对话顺序逐句练(上下文是意义的一部分);
2. **对话上下文常显**:画面上方是已完成句的 A/B 气泡流(含中文),
   当前句在下方用现有 TypingBoard 打字(说话人标签 + 中文提示);
3. **不写 SRS、不出解析撒花**:场景句无全套词性标注要求时跳过签名时刻
   (有标注则照常展开解析);练习记录写 log(报告页统计照常),
   计入试用版每日额度(它是正经练习)。

## 3. 技术方案

### 3.1 总原则

复用最大化:存储沿用 sentence 表与双库结构,练习复用 TypingBoard/
CompletionPage,生成复用工坊整条管线(拿满/回灌/查重/事件),校验复用
Validator——仅词表带约束放开。**新增概念只有一个:`pack` 标记。**

### 3.2 数据模型(唯一的 schema 改动)

```sql
-- store.rs SCHEMA 追加列(SQLite 幂等迁移:PRAGMA table_info 检查后 ALTER)
ALTER TABLE sentence ADD COLUMN pack TEXT NOT NULL DEFAULT '';
```

- `pack = ''`:普通等级句(现状,全兼容);
- `pack = "<场景包id>"`(如 `"cafe-order"` / 用户生成用任务场景名):
  场景对话句;`scene` 列存显示名,`func` 列存说话人(`"A"`/`"B"`),
  句序 = 表内自增 id 顺序(对话按写入顺序取)。
- `level` 列如实存**参考难度**(校验放开词表,模型/作者标注一个参考值,
  场景页仅作小字提示「参考难度:中级」,用 levels.ts 文案)。

**防污染(关键)**:等级练习的取句路径统一排除场景句——
`sentences_by_level` / `today_overview` 新句池 / `start_session` 加
`WHERE pack = ''`;新增 `sentences_by_pack(pack)` 与 `list_packs()`
(含出厂/用户双库,SQL 走 `DISTINCT pack`)。内容库「出厂句库/我的句集」
不变(天然只显 pack='');场景句由场景页承载。

**迁移**:`open_rw`/`open_readonly` 后做 additive migration(查
`PRAGMA table_info(sentence)` 无 `pack` 列则 ALTER;出厂库由 factory
重建自带)。用户已有 user_content.db 升级后 pack 全为 '' ✓ 行为不变。

### 3.3 出厂场景包内容(content/scenario/*.yaml)

```yaml
# content/scenario/cafe-order.yaml
pack: cafe-order
name: "咖啡店点单"
category: "餐饮"
intro: "从进门到取餐的完整点单对话。"
reference_level: L2          # 参考难度(不做校验约束)
dialogue:
  - { speaker: A, en: "Hi, what can I get for you today?", zh: "你好,今天想喝点什么?", words: [...], chunks: [...] }
  - { speaker: B, en: "Could I get a medium latte, please?", zh: "请给我一杯中杯拿铁。", words: [...], chunks: [...] }
  # … 8–16 轮,全标注(签名时刻可用);标注可用生成工坊按句补
```

factory build 扩展:读取 scenario/ 目录 → **无词表带校验**(复用
Validator 但传放开 band 的 spec:取 L6 spec 克隆后 `max_words=20` 沿用,
`vocab_band=0`)、结构/成分/音标/查重照旧强校验 → 按对话顺序
`insert_sentence(pack=...)`;包元数据(name/category/intro/参考难度)
入 `meta["scenario_packs"]`(JSON,同定级题库的存法,不加新表)。

首批内容生产:用生成工坊场景模式(M4 先行)按 §2.2 清单逐包生成 →
人工审校对话自然度 → 落 YAML。每包 12–16 句,共约 150 句。

### 3.4 生成工坊场景对话模式

- `JobParams` 增 `#[serde(default)] mode: GenMode`
  (`Level`(默认,老任务兼容)/ `Scenario`);
- **prompt 模板分支**(prompt.rs 新增 `build_scenario_prompt`):
  系统段 = 真实对话生成器(双角色、高频语块优先、每句 ≤20 词、
  美式日常口语、输出 schema 增 `speaker` 字段);用户段 = 场景 + 句数
  + 既有 avoid 指纹 + 回灌禁词(沿用);
- **校验**:词表带放开(同 §3.3 的放开 spec),其余管线原样
  ——拿满、修补、simhash 近重、精确同文、`workshop://activity` 全继承;
- **入库**:`pack = 任务场景名`,`func = speaker`,写用户库;
- UI:模式切换 chips;场景模式下隐藏等级下拉,完成 summary 文案
  「已生成场景对话,去「场景」页开练」。

### 3.5 后端命令(新增 3 个)

```rust
list_scene_packs(state) -> Vec<ScenePackInfo>
// { pack, name, category, intro, reference_level, sentence_count, origin: factory|user, practiced: bool }
// 出厂包元数据取 meta["scenario_packs"];用户包按 pack 分组即席构造(name=pack)
// practiced 由 log 表是否含该包句子的记录判定

start_scenario_session(state, pack: String) -> Session
// 按对话顺序(id 序)返回 items,全部 typing、不洗牌、is_review=false

delete_user_scene_pack(state, pack: String) -> ()   // 删除用户生成的整包
```

练习提交:复用 `submit_attempt`,新增 `#[serde(default)] skip_srs: bool`
——场景会话置 true 时仅写 log 不写 srs(试用限额照计)。

### 3.6 前端

- `App.tsx`:导航新增「场景」(💬,置于「生成工坊」之后);
  `PracticeLaunch` 增 `{ kind: "scenario"; pack; title }`。
- 新页 `ScenarioPage.tsx`:分类分组包卡片(出厂 + 我的)→ 详情抽屉
  (A/B 气泡预览)→ 开始练习;
- 新组件 `DialoguePractice`(桌面端页面级,复用 `TypingBoard`):
  上方气泡历史(A 左灰 / B 右蓝,含中文),打完一句推入气泡并前进;
  无标注句沿用 tokenizeFallback;完成页复用 `CompletionPage` +
  整段对话回放列表;
- `Workshop.tsx`:模式切换 + 场景模式表单变体;
- `ipc.ts` 补类型与封装(ScenePackInfo 等,serde 三处同步铁律)。

### 3.7 规范符合性与架构自检

- 纯逻辑仍在下沉层:排序会话可由 `start_custom_session` 思路直取,
  无新 sf-core 状态机需求(对话顺序 = 数据顺序);
- 数据驱动:分类/包/参考难度全在内容文件,扩包零代码;
- 离线红线:出厂场景包随 content.db 分发,**不接 AI 通道也可练**;
  生成自定义场景包才需通道(与工坊现状一致);
- 试用限额:场景练习计额(正经练习);SRS 池防污染见 §3.2;
- 术语规范:全程无 L1–L6/CEFR 字样,参考难度用阶段名。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 场景句污染等级每日队列 | §3.2 统一 `pack=''` 过滤;M5 专项回归(今日页计数在生成场景包前后不变) |
| 旧用户库无 pack 列 | 幂等 additive migration,失败即报错不静默;老行为全兼容(默认 '') |
| 生成的"对话"不像对话 | prompt 强制双角色轮替 + 语块优先;工坊卡片按 A/B 排版预览;人工审校后才进出厂包 |
| 对话句无全套标注 | 允许(打字练习用 tokenizeFallback,跳过解析);出厂包要求全标注,签名时刻可用 |
| 导航第 7 项拥挤 | 图标+双字标签与现有风格一致;若拥挤感明显,备选方案是并入内容库新 tab(记录备选,默认独立入口) |
| schema 版本前滚 | content.db 由 factory 重建无迁移问题;仅用户库走 ALTER,变更记录入 store.rs 模块注释 |
