# 内容生产手册 —— 出厂句库 5000 句怎么跑

> 对应规范 W6「全量生产 5000 句 + 抽审,否决率 ≤2%」。
> 覆盖面定义在 `content/scenes.yaml`,词表在 `content/lexicon/`,
> 产线代码在 `crates/sf-pipeline`(factory 档)。

## 0. 先看清楚现状

```bash
sf gold run                       # 词表分层 / few-shot / 种子回归,三关都得过
python - <<'PY'
import sqlite3
c = sqlite3.connect("content/build/content.db")
for lv, n in c.execute("select level,count(*) from sentence where pack='' group by level"):
    print(lv, n)
PY
```

2026-08-23 的基线:出厂库等级句 **50**(L1 20 / L2 20 / L3 10),**L4–L6 为 0**。
L4+ 空着意味着定级到中高级的用户没有出厂内容可练,默写也够不着。

## 1. 为什么必须先预扫,不能直接开跑

词表带是按**通用语料词频**(NGSL)划的,而场景要的词未必高频。实测:

| 场景 | 掉在哪 |
|------|--------|
| 看医生描述症状 | `fever` / `headache` / `sore` 不在 NGSL;`throat`(2327)、`stomach`(2673)在 L3/L4 越级 |
| 药店买药 | `pharmacy` / `prescription` / `painkiller` 全不在词表 |
| 餐厅点餐 | `dessert` / `fries` / `vegetarian` 越 L3 的 1500 带 |

一批 8 句能掉三成。5000 句跑到一半才发现某个领域的词全在词表外,
浪费的是已经花掉的额度和时间。**先扫一遍,把缺的词一次性补齐。**

## 2. 预扫

```bash
# 全量(68 个场景,每个试产 8 句,免费通道零成本,约 40 分钟)
sf factory scan --count 8 --out doc/assets/scan-report.md

# 只看某个类别
sf factory scan --category 医疗 --count 8

# 先小样试跑
sf factory scan --limit 5
```

扫描在每个场景**最低**的目标等级上做 —— 词表带最紧,最容易暴露缺词。

报告给三样东西:

1. **需要补词的场景表**(场景 / 类别 / 扫描等级 / 入库率 / 词表外 / 越带)
2. **候选词条**,可直接粘进 `content/lexicon/supplement.tsv`;band 按
   "最早需要该词的等级"给,落在下一级 —— 宁可判越级由分诊改级救回,
   也不要让低等级冒生词。**IPA 与中文释义需人工补齐**
3. **越带词清单** —— 这些不必补表,分诊会把句子改存到合适等级;
   但值得知道哪些场景会被系统性推高

### 词频 ≠ 难度:第三张表

预扫还会暴露另一类问题 —— 词**在**表里,但 band 定得不合教学常识:
`hello` 2811、`milk` 950、`red` 700、`bag` 600、`rice` 2800。band 取自 NGSL 的
**通用语料词频**,不是学习难度,于是 L1 连一个颜色词、一样食物都用不了。

不能直接改 `band`:**定级测试**按它分层估算考生词汇量,把 `milk` 从 950 改到
220 会让「认识 milk」只记 220 词,考生被低估、误路由到更低的起步等级。

所以拆成两个数,`content/lexicon/overrides.tsv` 只改 `teach_band`:

```
lemma <TAB> teach_band <TAB> 理由
hello	30	初学第一个词;NGSL 2811 反映的是书面语稀有度,不是难度
milk	220	A1 饮品,点单第一课
```

选词标准:只收**具体、可指认、初学者头几课就会遇到**的词(CEFR A1 → 500 以内,
A2 → 1000 以内);抽象词与低频义项一律不动,交给 NGSL。

### 补词后必做

```bash
sf gold run                # 会拦住"补充表重定义了 base 已有的词"
sf factory build           # 桌面端只读 content.db 的 lemma 表,不重建等于没改
```

> `supplement.tsv` **不得重定义** `base.tsv` 已有的词。悄悄改一个已有词的
> band,等级归属就会莫名其妙地漂移(踩过:把 `noodle` 从 1500 改成 1550,
> 种子句 "We ordered two bowls of noodles." 当场在 L3 判越级)。

## 3. 摸底通过率

补完词再抽几个场景验一下,别急着全量:

```bash
sf factory yield --level L4 --scene "看医生描述症状" --count 20 --save /tmp/med.txt
# 改了校验器/分诊之后,拿同一批原始产出零成本复测:
sf factory yield --level L4 --replay /tmp/med.txt
```

2026-08-23 修完产线 + 补齐词表后的**跨等级摸底**(L1/L3/L5 各两场景,115 句):

| 级 | 场景 | 样本 | 本级 | 改级 | 丢 |
|----|------|------|------|------|----|
| L1 | 告别与约下次 | 20 | 20 | 0 | 0 |
| L1 | 超市购物 | 20 | 20 | 0 | 0 |
| L3 | 询问菜品与推荐 | 20 | 17 | 1 | 2 |
| L3 | 邮寄快递 | 15 | 15 | 0 | 0 |
| L5 | 医嘱与康复 | 20 | 20 | 0 | 0 |
| L5 | 面试自我介绍 | 20 | 20 | 0 | 0 |

**入库 98% · 本级 97% · 改级 1% · 丢弃 2%。** 速度 ~66 秒 / 20 句。

剩下的 2 句丢在「成分索引越界」—— 模型自己把 chunk 索引写错了,与词表无关。
这是模型质量的地板(1.7%),不该靠改词表去追;5% 人工抽审那一关会兜住。

> `本级` 与 `改级` 要分开看:改级的句子没丢,但产不出**本级**内容。
> 只看"入库率"会误以为低等级的量够了。第一轮摸底本级只有 83%,
> 补完场景词与教学定级后才到 97%。

## 4. 正式跑批

```bash
sf factory gen --scene "看医生描述症状" --level L4 --count 20 \
  --channel opencode --model opencode/hy3-free \
  --db content/build/content.db
```

按 `content/scenes.yaml` 的 `levels` 逐场景逐等级跑;每级的批次数 =
`ceil(目标 ÷ 该级场景数 ÷ 每批句数)`,`sf factory scan` 的开头会把这张
表算给你。

### 成本与排期(免费通道)

| 项 | 数 |
|----|----|
| 纯生成 | ≈5 小时(单线程) |
| 实际墙钟 | 8–12 小时,分几天跑(免费通道会限速,有退避) |
| 费用 | ¥0;走 DeepSeek 兜底约 ¥7 |
| content.db | 0.27MB → ≈3.2MB;NSIS 压缩后安装包约 +1MB |

限速由 `BackoffPolicy` 处理,连续 3 次 429 会建议换通道。

## 5. 抽审(出口标准)

规范要求 5% 人工抽审,**否决率 >2% 就整批复审**,否决样本回灌反例库。
校验器只保证"结构对、词在带内、不重复",保证不了"这句话母语者真会这么说" ——
那部分只能靠人看。

## 6. 上线

内容包随 `rev` 分发,用户句库永不被触碰。发布流程见
《构建与发布手册》与《发布到GitHub-Releases指南》。

**注意**:`content.db` 是随包分发的只读资产,改了词表或句库就得连它一起发,
否则用户侧看不到任何变化(桌面端不读 `content/lexicon/*.tsv`)。
