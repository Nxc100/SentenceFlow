## 1. 产品是什么

**句流 SentenceFlow** 是一款面向中国学习者的**买断制单机英语整句输出训练软件**。

核心玩法一句话:**看中文、打英文;答对的瞬间,句子自动展开成「音标 + 词性 + 句子成分」的彩色解析**。

四条产品定性:

| 定性 | 落地方式 |
|---|---|
| **单机** | 无账号、无服务器、无登录;全部学习数据存本机 SQLite |
| **离线可用** | 出厂内置六级全标注句库 + 8 个情景对话包 + 定级题库,零配置即可练 |
| **免费** | 当前发行形态 = 免费版:装上即全功能,无需激活、无试用期、无每日上限 |
| **AI 可选** | 四条 AI 通道全部为**增量能力**;不配置任何通道,学习功能 100% 完整 |

> 买断制的完整实现(离线 Ed25519 许可证 + 14 天试用 + 到期体验模式 + 签发 CLI)
> 原样保留在代码里,由 `licensing.rs` 的 `FREE_EDITION` 常量切换,见 [第 8 章](#8-发行形态免费版与保留的买断制实现)。

**"签名时刻"是产品灵魂**:答对后 720ms 内依次发生 —— 下划线消融 → 单词按句子成分聚拢成彩色卡片 → 词性胶囊逐个弹入 → 音标浮现 → 撒花 + 正确音 → 自动朗读 → 中文与讲解入场。颜色本身即教学信息(14 种词性 / 8 种成分各有固定色),不是装饰。

## 2. 系统架构总览

### 2.1 仓库布局

```
crates/
  sf-core/        纯逻辑核心(无 IO、无时钟、无 OS 随机):LevelSpec 解释、
                  Leitner 五盒 SRS、每日会话编排、逐词判定(LCS diff)、
                  报告统计折叠、定级测试状态机、确定性 RNG
  sf-pipeline/    统一生成管线:prompt 装配、流式 JSON 增量解析、
                  确定性校验器、factory/user 双档分诊、simhash 查重、
                  NGSL 词典;feature "store" = SQLite 内容库;
                  feature "factory" = `sf` 工厂 CLI
  sf-llm/         四通道适配(同一 ChannelAdapter trait)、计量双轨、
                  指数退避、系统钥匙串、可续跑任务队列状态机、
                  微基准打分、channels.json 远程策略
  sf-license/     离线授权:.sflic Ed25519 本地验签 + 试用状态机;
                  feature "issuer" = 签发 CLI(绝不进发行二进制)
  sf-wasm/        sf-core 的 wasm-bindgen 绑定(JSON 字符串 ABI)
apps/
  desktop/        Tauri 2 桌面端(售卖主体)
    src-tauri/    Rust 壳:63 个 command、16 个事件通道、
                  progress.db、工坊 runner、聊天后端、技能面板后端、
                  opencode 安装器、piper TTS、授权编排
    src/          React 18 + TypeScript 前端:8 个一级页面(今日练习 / 我的句库 /
                  情景对话 / AI 造句 / AI 聊天 / 学习报告 / 我的水平 / 设置)
                  + 4 个全屏流程(首启选级 / 定级测试 / 练习 / 情景对话练习)
  web-trial/      Web 试用版(纯静态站):L1–L2 各一节,IndexedDB 进度可导出
packages/ui/      共享 React 组件 + 设计令牌(浅色/深色/护眼纸色/马卡龙少女)+
                  练习引擎组件 + 签名时刻动效 + WebAudio 音效
content/          specs/*.yaml(六级 LevelSpec,单一事实源)· seed/(种子句库)
                  · scenario/(8 个出厂情景包)· placement/(定级题库)
                  · lexicon/(NGSL 全量词典)· channels.json
tools/
  audit/          spaCy 离线抽审脚本(纯 QA,不在运行时依赖树)
```

### 2.2 三条数据流

**① 学习流(零网络)**
```
content.db(只读,随包)  ──┐
                          ├─→ ContentIndex ─→ sf-core 纯函数 ─→ progress.db
user_content.db(读写)  ──┘        ↑
                              LevelSpec(来自 content.db 快照)
```
练习路径**不链接 sf-llm**,架构上无法发起网络请求。

**② 生成流(可选,联网)**
```
用户描述场景 → sf-pipeline::build_prompt → sf-llm::ChannelAdapter(四选一)
  → 流式文本 → StreamScanner 增量解析 → Validator 确定性校验
  → triage 分诊 → Accept 入 user_content.db / Repair 修补 / Discard 可捞回
```

**③ 聊天流(可选,联网)**
```
chat_thread/chat_message(progress.db)
  ├─ free/roleplay → ChannelAdapter::chat_stream(四通道)
  └─ agent        → 直驱本机 opencode CLI(用户选定工作目录)
```

### 2.3 五条架构不变量(代码强制,非口头约定)

1. **练习路径零网络调用** —— sf-core 与练习 UI 不依赖 sf-llm;全部网络请求只出自
   生成工坊 / AI 答疑 / 周点评 / AI 聊天四个入口。
2. **LevelSpec 是单一事实源** —— 生成约束、校验反查、练习行为读同一份 YAML;
   引擎里没有任何按等级写死的分支。spec 快照随 content.db 一起分发,内容与行为同版。
3. **校验器是契约** —— LLM 输出必须过确定性校验才能入库;模型再不可靠也不产出破碎数据。
4. **隐私红线** —— API Key 只进系统钥匙串,备份包结构上不含密钥;
   绝不读取用户的 opencode 凭据(通道可用性仅经 `opencode models` 输出间接判定)。
5. **双端逐比特一致** —— `now`/`seed` 全是显式参数,桌面(native)与试用版(wasm)
   对同一输入产生完全相同的行为。

## 3. 内容与数据资产

### 3.1 LevelSpec:六级课程规格(`content/specs/L1..L6.yaml`)

一个 YAML 文件定义"一个等级是什么",同时约束**生成 / 校验 / 练习**三端:

| 字段 | 作用 |
|---|---|
| `vocab_band` | NGSL 词表带上限(前 n 词;0 = 不限,仅 L6) |
| `max_words` | 句长上限(词数) |
| `grammar_whitelist` | 语法白名单(生成约束 + 校验反查的标签集) |
| `can_do` | 该级典型能力描述(等级卡与 AI 聊天难度提示都取它) |
| `practice.flow` | 首遍流程:`reorder_then_typing` / `typing` / `mixed` |
| `practice.review_listening_ratio` | 复习句转听打的比例(0 = 该级未解锁听打) |
| `practice.dictation_min_box` | 盒 ≥ 此值的句子进入默写(0 = 未解锁) |
| `practice.hints` | 音标显示策略(常显/点击/隐藏)、首字母提示、中文可否隐藏 |
| `practice.judge` | 严格模式默认值、冠词介词专项统计开关 |
| `practice.srs` | 每日新句默认/范围、复习上限、五盒间隔、盒 5 抽检间隔、听打权重 |

六级实际配置(已实现并随包分发):

| 等级 | 展示名 | CEFR | 词表带 | 句长 | 首遍流程 | 听打比例 | 默写 | 音标 | 判分 |
|---|---|---|---|---|---|---|---|---|---|
| L1 | 入门 | A1 | 500 | 8 | 先重组后打字 | — | — | 常显 | 宽松 |
| L2 | 初级 | A1+ | 1000 | 10 | 先重组后打字 | — | — | 常显 | 宽松 |
| L3 | 中级 | A2 | 1500 | 12 | 直接打字 | 30% | — | 点击显 | 严格 |
| L4 | 中高级 | A2+/B1 | 2000 | 14 | 直接打字 | 30% | — | 点击显 | 严格 |
| L5 | 高级 | B1 | 2800 | 16 | 打字/听打混合 | 40% | 盒 ≥3 | 隐藏 | 严格 |
| L6 | 精通 | B1+/B2 | 不限 | 20 | 打字/听打混合 | 40% | 盒 ≥3 | 隐藏 | 严格 + 冠介专项统计 |

> 其余按级差异:首字母提示仅 L1–L2 开启;「中文可隐藏」(`zh_hideable`)仅 L5–L6 开启;
> 五盒间隔 L1–L2 为 `[1,2,4,7]` 天 + 12 天盒 5 抽检,L3–L4 为 `[1,3,7,14]` 天 + 30 天抽检,
> L5–L6 为 `[1,3,7,14]` 天 + **21 天抽检**(高段抽检加频);
> 每日新句默认值 L1–L2 = 10、L3–L4 = 20、L5–L6 = 25,用户可在 5–50 间自调;
> 到期复习上限统一 60 句,听打权重统一 1.5×。

> LevelSpec 自身带一致性校验(`daily_new_default` 必须落在 range 内、
> `listening_weight ≥ 1.0`、`review_listening_ratio ∈ [0,1]` 等),
> 不合法的 spec 在构建期就失败。

### 3.2 词典(`content/lexicon/base.tsv`)

- **2828 条** `lemma \t band \t ipa_gb \t ipa_us \t zh_gloss`,来源 NGSL v1.01(CC BY 3.0,应用内署名)。
- 承担两件事:**词表带查询**(越级判定)与 **IPA 对账覆写**(音标漂移归零)。
- 查询链:精确 → 不规则形(irregular map)→ 后缀剥离启发式(复数/过去式/进行时/比较级)→ 缩写(`I'm` / `don't`)。
- 词典整表随 `content.db` 的 `lemma` 表分发,客户端启动时装载为运行时 `Lexicon`,
  兼作**定级测试的词汇候选池**(按 band 分层抽样)。

### 3.3 种子句库(`content/seed/L1..L3.yaml`)

- 当前 **50 句**(L1 20 / L2 20 / L3 10),全部手写、全标注(逐词 IPA + 词性 + 成分块 + 句型公式 + 一句话讲解)。
- 与 AI 生成句走**同一条校验管线**;`sf factory build` 时任何一句不过校验即构建失败。
- 兼作**金标回归集**(`sf gold run`)。

### 3.4 出厂情景对话包(`content/scenario/*.yaml`)

8 个包、**82 轮对话**,A/B 双角色连贯对话,不分等级:

| 包 id | 名称 | 分类 | 轮数 |
|---|---|---|---|
| `cafe-order` | 咖啡店点单 | 餐饮 | 14 |
| `hotel-checkin` | 酒店入住登记 | 出行 | 11 |
| `airport-checkin` | 机场值机与安检 | 出行 | 10 |
| `restaurant-order` | 餐厅点餐与结账 | 餐饮 | 10 |
| `first-meeting` | 初次见面寒暄 | 社交 | 10 |
| `pharmacy` | 药店买药 | 医疗 | 10 |
| `taxi-directions` | 打车与问路 | 出行 | 9 |
| `supermarket-checkout` | 超市购物与结账 | 购物 | 8 |

构建期强校验:包 id 唯一、`speaker` 必须是 A/B、每包 ≥6 轮、包内查重;
**词表判定整体关闭**(真实生活词如 latte / checkout 本就不在 NGSL 2827 词内),
结构 / 成分覆盖 / 音标 / 句长 / 查重照旧强校验。

### 3.5 定级题库(`content/placement/placement.yaml`)

- **词汇快筛配置**:6 个 NGSL 分层 `[300, 600, 1100, 1600, 2200, 2800]`,每层抽 3 个真词,
  外加 6 个伪词(题库共 12 个候选伪词)做猜测校正。
- **定级句 48 句**(每级 8 句),按各自等级 spec 走完整校验管线。
- **边界语法题 20 题**,覆盖 L1–L2 … L5–L6 五个相邻边界,每边界 ≥4 题、二选一、挖空句必须含 `___`。
- 构建期红线:伪词不得是词表内真词、必须 3–9 个小写字母;每级定级句 ≥6 句;
  语法题边界必须相邻、答案下标不得越界。任何一条不过 → `sf factory build` 失败。

### 3.6 通道策略(`content/channels.json`)

无服务器的"远程开关",随内容包分发,应用启动读取(三级回退:app-data 副本 → 随包资源 → 内置默认):

| 字段 | 作用 |
|---|---|
| `enabled` | 每通道启用位(缺省视为启用),可远程停用某条通道 |
| `notices` | 每通道人话提示(通道卡预期管理) |
| `opencode_known_bad` | 已知有问题的 opencode 版本(子串匹配,命中即禁用) |
| `proxy_required_models` | 国内直连不可用、需代理的模型名单(实测数据驱动) |
| `npm_registries` | 一键安装 opencode 的 npm registry 候选(国内镜像在前) |
| `deepseek_prices` | 价格表 + `prices_updated_at`(过旧时 UI 显示 ⓘ) |
| `default_microbatch` | 微批大小默认值 |
| `free_list_fingerprint` | 免费模型名单指纹,变化即触发重跑微基准 |

### 3.7 三个数据库

| 库 | 位置 | 读写 | 内容 |
|---|---|---|---|
| `content.db` | 随包资源 | 只读 | `sentence` / `lemma` / `level_spec` / `meta`(含 `scenario_packs`、`placement`、`spec_hash`、`rev`) |
| `user_content.db` | app-data | 读写 | 用户生成 / 导入的句子与场景包(同一 schema,`meta.origin = user`) |
| `progress.db` | app-data | 读写 | `srs` / `log` / `kv` / `spend` / `gen_queue` / `bench` / `favorite` / `chat_thread` / `chat_message` |

- 两个内容库经 `ContentIndex` 统一读取,用户库 id 加 `1_000_000_000` 偏移进入同一 id 空间,
  练习引擎对"句子来自哪个库"完全无感。

- **幂等加列迁移**:`sentence.pack`、`chat_thread.channel/model/model_label`、
  `chat_message.todo_json/zh` 都走"缺哪列补哪列"的 `ALTER TABLE`,
  已发出去的旧库升级后行为完全兼容。

## 4. 学习功能(不需要联网的全部功能)

### 4.1 首启与等级选择

- **首启零配置**:未定级时进入等级选择页,六张等级卡各带"能做到什么"(取自 `spec.can_do`),
  点一张即开练。**通道配置绝不出现在首启路径**。
- 也可点「不确定?帮我测一下(约 3 分钟)」进入真实的水平测试。
- 界面**全程不露 L1/L6/CEFR 术语**:统一显示"入门 / 初级 / 中级 / 中高级 / 高级 / 精通 · 能做到:打招呼、自我介绍"。

### 4.2 英语水平定级测试(三阶段 MST)

状态机在 `sf-core::placement`(纯逻辑、可复现),前端只做呈现与作答转发。
**全程不写 SRS、不记练习日志、不占体验模式每日额度。**

**阶段一 · 词汇快筛(进度 0–40%)**
- LexTALE 式"认识 / 不认识"判断:按 NGSL 分层从词典抽真词 + 抽伪词,整体洗牌。
- 词汇量估计做**猜测校正**:每层 `width × max(0, (命中率 − 伪词误报率) / (1 − 伪词误报率))` 累加。
- 伪词误报率 > 0.5 → 标记**低信度**,最终等级保守下调一级。
- 词汇量 < 150 → **零基础直通入门**,不进整句阶段(不让新手挫败地打句子)。
- 否则按词汇量路由起步能力值 θ:< 400 → 1.0;< 1400 → 2.5;否则 4.0。

**阶段二 · 整句实测(进度 40–90%,固定 7 题)**
- 复用真实练习组件:低档首题用**拆句重组**(门槛最低),高段隔题**听打**(TTS 不可用时自动退化为打字),其余打字。
- 每题按词级错误判定方向:错 ≤1 → 升;错 ≥3 或看过答案 → 降;之间为中性。
- **阶梯自适应**:方向反转时步长减半(最小 0.25),θ 夹在 [1, 6]。
- 当前 θ 对应级题目耗尽时**就近借题**(-1, +1, -2, +2 …)。

**阶段三 · 边界语法加测(进度 90–100%,仅在需要时触发)**
- 触发条件(任一):θ 卡在半级上(距整级 > 0.4)、阶梯从未收敛(步长仍 > 0.25)、来回震荡(反转 ≥2 次)。
- 从题库取该边界的 4 道二选一语法题;答对 ≥3 取高级,否则取低级。
- 结果页给人话解释:「「一般过去时」已掌握」/「…还需巩固」。

**结果页**
- 展示推荐等级(阶段名 + can-do)、估计词汇量、整句词级正确率、低信度提示、语法结论。
- **保守修正**:低信度或"整句结论与词汇量推断相差 ≥2 级"时下调一级(宁可偏易勿偏难)。
- **必须用户确认才改等级**,绝不静默切换。结果持久化在 `progress.db` 的 kv 里,设置页与「我的水平」页可回看。

### 4.3 今日练习与 SRS 排程

**今日页**四张统计卡 + 一个主按钮:到期复习 / 可学新句 / 连续打卡 🔥 / 今日已练。
无红点、无促销 —— 心流优先。空态给出可行动的三条出路(切等级 / 去句库自由练 / 用 AI 造句)。

**每日队列构建**(`sf-core::session::build_session`,纯函数):
1. **到期复习优先**:`due_at ≤ now` 的句子按"最过期优先"排序,截断到 `review_cap`(60);
   被截掉的数量作为 `overflow_reviews` 返回,前端提示"到期复习较多,今天先安排 N 句"。
2. **新句补足**:未见过的句子按课程顺序取到每日新句配额(用户设置值被夹进 spec 的 range)。
3. **模式指派**(全部数据驱动,无硬编码):
   - 复习句:盒 ≥ `dictation_min_box` 时 50% 概率转**默写**;否则按 `review_listening_ratio` 概率转**听打**;其余打字。
   - 新句:打字,并按 `flow == reorder_then_typing` 打上 `reorder_first` 标记。
4. **混排**:确定性 Fisher–Yates 洗牌。
5. **种子 = 本地日序号** → 同一天内退出再进来,队列完全一致。

**Leitner 五盒 SRS**(`sf-core::srs`):

| 结果 | 行为 |
|---|---|
| 答对 | 进度 += 权重(听打 1.5×,其余 1.0);每满 1.0 进一盒;按新盒的 spec 间隔排下次到期 |
| 答对(盒 5) | 留在盒 5,按 `box5_recheck_days` 排下次抽检 |
| 答错 | 错误计数 +1,**直接回盒 1**,当天立即可重练 |
| Ctrl+M 标记掌握 | 直入盒 5,按抽检间隔排期 |
| Ctrl+Q 标记不熟悉 | 回盒 1,永久标记,收录错题本 |

- **掌握口径**:盒 ≥ 4。
- **错题本收录条件**:错 ≥2 次 **或** 标过不熟悉(由 `srs` 表派生,不单独建表)。
- **看过答案**仍推进 SRS,但会被记录,报告里不计入连对纪录。

### 4.4 四种练习模式

练习是**全屏模态**,顶栏常驻返回按钮(任何加载态 / 空态都出得去),底栏常驻「‹上一题 / 下一题›」+ 随视图切换的快捷键提示条。

#### 打字(Typing)
- 逐词字格,词满后继续敲键**自动落入下一个未完成词**;点击词格可直接定位。
- **严格模式**(默认):错字**不上屏** —— 词格抖动 240ms + 红字原位闪现 200ms + 错误音;全部打对自动提交。
- **宽松模式**:错字上屏标红,Enter 整句校验,错误词清空重打。
- `↓` 在格内以浅灰揭示答案(记 `seen_answer`);`Enter` 在未完成时定位到第一个错/未完成词。
- **Ctrl 单击**(keyup 且无组合键)朗读整句。
- 实时统计:错误数、是否看过答案、用时、WPM(按词数/分钟)。
- 无标注的导入句自动按空白分词兜底,可正常打字(跳过解析页)。

#### 拆句重组(Reorder)
- 打乱词块,拼回正确顺序;**全键盘可操作**:数字键选词、←→ 移动、空格选中。
- L1–L2 的新句默认"先重组后打字"(可在设置里覆盖);重组通过后直接衔接打字二遍。

#### 听打(Listening)
- 进入题目自动播放一遍(400ms 后),中文题面隐藏,凭听力打出整句。
- 答对按 **1.5× 权重**推进 SRS(比打字更快升盒)。
- L3 起按 `review_listening_ratio` 在复习句中随机解锁。

#### 默写(Dictation)
- 只显中文,自由文本框输入整句,Enter 校验。
- 判定走 `sf-core::judge` 的 **LCS 对齐 diff**,逐词给出四种判词:
  **对**(绿) / **错**(红删除线 + 附正确词) / **漏词**(灰占位) / **多打的词**(红删除线)。
- 判定策略:大小写不敏感、忽略标点(句末标点直显不输入)。
- **L5 起**解锁:盒 ≥ `dictation_min_box`(L5/L6 均为 3)的复习句有 50% 概率转默写。

#### 全局快捷键

| 键 | 作用 |
|---|---|
| `Ctrl`(单击) | 朗读整句 |
| `Ctrl + M` | 标记掌握(直入盒 5) |
| `Ctrl + Q` | 标记不熟悉(回盒 1 + 收录错题本) |
| `Esc` | 暂停 / 关闭答疑抽屉 |
| `Shift + ←/→` | 上一题 / 下一题 |
| 解析页 `空格` / `Enter` | 下一题(动效定格后才生效) |
| 解析页 `←/→` | 朗读整句 |

### 4.5 签名时刻(解析视图)

答对后进入解析视图,时间轴严格定义:

```
t0     下划线淡出
+160ms 单词按句子成分聚拢成彩色卡片(8 色成分),逐张弹性落位(错开 70ms,带成分色光晕)
+300ms 词性胶囊 stagger 弹入(14 色词性)
+380ms 音标浮现
+420ms 撒花(1.8s)+ 庆祝上行三音 C6–E6–G6
+500ms 自动朗读整句
+700ms 中文与「句子解析」入口入场
```

- **撒花的两条实现要点**(都是"用户说看不见"改出来的,细节见 `packages/ui/src/confetti.ts` 头注):
  颜色**运行时读当前主题的语法色板文字色**,而不是规范原文的近白底色系(那组压在浅色底上
  对比只有 ~1.1:1);构图是「中心一炸 + 底部两侧礼炮」,因为 +720ms 就能按空格走人,
  多数用户只看得到前 300ms。粒子按视口面积 120–200 粒。

- **任意按键跳到终态**;跳过用的那次按键**不向页面层透传**,所以"空格进下一题"永远作用于已定格的画面。
- 动效自然结束或被跳过都会触发 `onSettled`,页面层据此启用"空格/Enter 下一题"。
- **减少动效**(系统偏好或设置项)时降级为直接终态、无撒花。
- 解析页提供「问 AI」按钮(配了通道才有效)。

### 4.6 情景对话(场景练习)

不分等级的整段对话练习,与等级 SRS 完全隔离。

**场景列表页**
- 按分类分组(出行 / 餐饮 / 社交 / 购物 / 医疗 / 我生成的),分类顺序沿用内容包给出的顺序,「我生成的」永远排最后。
- 每张卡显示名称、句数、参考难度小字、已练进度;练完全部显示 ✓。
- 分类标题上有「🗑 清空我生成的(N)」批量删除(出厂包自动跳过、不受影响,二次确认)。
- 空态引导去「AI 造句 · 场景对话」自己造一个。

**详情预览弹窗**
- 完整 A/B 对话逐句预览(英文 + 中文);Esc 关闭。
- 三个出口:「开始练习」/「从第 N 句继续」(断点续练)/「和 AI 实战演练」(直跳 AI 聊天角色扮演)。

**对话练习页**
- 按对话顺序逐句练、**不洗牌**、全部打字模式。
- 上方是已完成句的 **A/B 气泡流**(上下文即意义),下方用打字板打当前句。
- 跳过的句子在回放里标出、不计入正确率。
- **只记练习日志、不写 SRS**(`skip_srs`),报告页照常统计,但不会污染等级复习队列。
- 完成页给统计与回放。

**断点续练**:从开头数连续练过的句子数即为下次的起点 —— 中间跳过的不算,回来正好接着第一个没练过的句子。

### 4.7 我的句库

四个页签 + 分页 + 批量操作:

| 页签 | 内容 | 特有操作 |
|---|---|---|
| 出厂句库 | 随包句子,按等级 + 场景分组 | — |
| 我的句集 | 生成 / 导入的句子(用户库) | 双列导入、按场景批量删除、单句删除 |
| 错题本 | `err ≥ 2` 或标过不熟悉 | 一键"错题重练" |
| 收藏 | 收藏的句子 | 一键"自由练习" |

- **分页**:每页 20 句,换页签 / 等级 / 场景自动回到第 1 页(不会停在越界页显示空列表)。
- **点句展开解析**(无撒花的 ParseView),可朗读、可收藏。
- **双列导入**:粘贴"中文 <Tab> 英文"文本批量导入到用户库;导入句无标注,按打字模式练习(跳过解析页),后续可用工坊补全解析。
- **场景签**按来源取:出厂页签用出厂场景,我的句集用生成任务的场景名。
- 出厂句库**不可删除**(后端硬拦截)。

### 4.8 学习报告

- **今日卡**:练习次数、正确数、用时、平均 WPM。
- **热力日历**:按可用宽度自适应显示 12–53 周(窗口最大化后直接看满一年,ResizeObserver 实时响应)。
- **WPM / 正确率曲线**:SVG viewBox 拉伸铺满,`vector-effect: non-scaling-stroke` 保线宽。
- **薄弱分析**:按**词性**与**句子成分**两个维度统计错误归因,给出错误数与占比排名。
  每条薄弱项带「AI 加练」按钮 → 直跳生成工坊并预填该场景。
- **连续打卡(火苗)**:从最新有记录的一天往回数连续天数。
- **最佳连对**:看过答案的答对不计入连对。
- **周报导出**:报告页带 `@media print` 版式,走系统打印对话框「另存为 PDF」,A4 一页。
- **时区正确**:日界线由前端传入 UTC 偏移(`-getTimezoneOffset()*60`),后端不猜。

### 4.9 我的水平

左侧栏一级入口:
- 当前练习等级 + 能做到什么;
- 「测一测 / 重新测一下我的水平」(约 3 分钟:认词 + 打整句 + 选语法);
- 六张等级卡手动切换;
- 上次测试结果详情(等级、估计词汇量、整句正确率、语法结论、测试时间)。

### 4.10 语音朗读

- **优先离线**:piper sidecar(`en_GB-alba-medium` / `en_US-lessac-medium`),
  按 `(文本, 音色, 语速)` 哈希缓存 wav,重复播放直接命中缓存。
- **自动回退**:piper 资源不存在时返回 `None`,前端无缝回退 WebView 的 `speechSynthesis` —— 练习永不因为音频阻塞。
- 支持英式 / 美式切换与 0.6–1.4× 语速(设置项)。

### 4.11 音效

WebAudio 实时合成,**无音频资源文件**:
- 按键音三音色(关 / 软触 / 机械),随机 ±3% 音高避免机械重复感;
- 正确音"叮" 880Hz · 90ms;错误音 220Hz(刻意比正确音更轻);
- 掌握音上行双音。
- 音量 0–100 可调;同类音效重触发时先截断上一次(不叠播);
- AudioContext 惰性创建于首次用户输入(遵守浏览器自动播放策略)。

## 5. AI 功能(可选,全部为增量能力)

> 不配置任何通道时:AI 造句显示引导卡、AI 聊天显示引导、答疑与周点评按钮不可用 ——
> **其余所有学习功能完整可用**。

### 5.1 四通道体系

四条通道实现同一个 `ChannelAdapter` trait(`probe` / `complete_stream` / `chat_stream` / `meter`),上层完全通道无关:

| 通道 | 形态 | 传输 | 计量 | 费用 |
|---|---|---|---|---|
| **opencode 本地** | 驱动本机 opencode CLI | `run --format json`,prompt 走 stdin,沙箱 cwd | 请求桶 | 0(限速) |
| **DeepSeek 官方** | HTTPS OpenAI 兼容 | SSE 流 | 按 token 计价 | 按量,预算硬顶 |
| **Zen 直连** | HTTPS OpenAI 兼容(`opencode.ai/zen/v1`) | SSE 流 | 请求桶 | 免费模型 0 |
| **Ollama 本地** | localhost:11434 的 `/v1` | SSE 流 | 请求桶 | 0,全离线 |

**opencode 通道的实现细节**(全部经真机 spike 钉死):
- 二进制定位链:手动指定路径 → PATH → 常见安装目录(`~/.local/bin`、`~/.opencode/bin`、`%LOCALAPPDATA%\Programs\opencode`、`/usr/local/bin`、`/opt/homebrew/bin`),Windows 下认 `opencode.exe` / `opencode.cmd` / `opencode`。
- **Windows 下 `CREATE_NO_WINDOW`**:GUI 进程 spawn `.cmd` 不再弹黑色控制台窗口。
- **我方托管沙箱**:每次运行前把 `opencode.json`(agent `sf-gen`,`edit/bash/webfetch` 全 deny)写进沙箱目录,以此为 cwd。
- **探测只读**:`--version`(20s 超时,兼容慢磁盘 / 虚拟机冷启动)+ `models`(45s);**从不打开 `auth.json`**。
- 免费模型**匿名可用、无需登录**;名单为空时呈现为「重试 + 备用登录」,而不是把登录当必经步骤。
- 事件解析容错:JSON 行取 `text`/`content`/`delta`/`part.text`,非 JSON 行原样透传,结构事件跳过。

**代理支持**:用户可在设置里填本机 HTTP 代理端口;opencode 子进程经
`HTTP_PROXY/HTTPS_PROXY` 环境变量(`NO_PROXY=localhost,127.0.0.1`),
HTTP 通道经 reqwest Proxy;**Ollama 本地永不走代理**。

### 5.2 计量双轨:永不静默烧钱

**付费轨(MoneyMeter)**
1. **发车前预估**:prompt token 估算 × 单价 + 预期输出 token × 单价,显示在 CostBar;
2. **流中实时累加**:每个文本块估算输出 token,实时更新费用;
3. **≥80% 预算** → CostBar 转警告色;
4. **触顶** → **硬停止**,优雅收尾:丢弃流、保留已入库句子、明确告知"已达单次预算上限,已入库完成部分";
5. **usage 回填**:后端返回真实 usage 后覆盖估算值,并记入 `spend` 表。
- Token 估算刻意偏高保守(ASCII 词 ≈1.3 token,中日韩字符 ≈1 token,其余符号 4 字符 ≈1 token);
  UI 恒标"以官方账单为准"。
- 单次预算默认 ¥1,可调;支持月度提醒阈值;支持用户手改价格表(覆盖 channels.json)。

**免费轨(RateBudget)**
- 客户端令牌桶(按 RPM 估计值),外加每日请求计数(CostBar 免费形态右侧展示)。
- 429 时走**可视化指数退避**:8s → 16s → 32s → 60s 封顶;服务端 `Retry-After` 优先;
  界面显示倒计时"免费额度限速,N 秒后自动继续";**连续 3 次限速后建议切换通道**。

**消费统计**:`spend_summary` 给出今日 / 近 30 天滚动窗口的请求数与费用,
工坊页与设置页均可见;聊天、答疑、工坊、智能体的用量分别打标记入库。

### 5.3 通道配置与一键安装(设置 · AI 接入)

- **四张通道卡**,每张实时探测出**四态**:🟢 就绪 / 🟡 未登录或未配 Key / ⚪ 未安装或未启动 / 🔴 错误(附人话原因)。
- **一键安装 opencode**(Windows,**免 Node、免终端**):
  - 从 npm registry(国内镜像优先,名单来自 channels.json)下载官方平台包 tgz → 解出 exe →
    放进 `%LOCALAPPDATA%\Programs\opencode` → `--version` 健康检查 → 写入 `settings.ai.opencode_bin` 即刻生效;
  - 顺带把安装目录**追加进用户 PATH**(HKCU,免管理员,自动广播 `WM_SETTINGCHANGE`),新开的终端可直接用 `opencode` 命令;
  - 进度经 `install://progress` 流式上报(获取版本 / 下载 MB / 解包 / 校验);
  - **老 Windows 三层防护**:`RtlGetVersion` 探测真实 build 号,低于 17763(Win10 1809)直接给出人话说明并建议改用 Zen 通道;
    进程启动时设置 `SetErrorMode` 抑制系统级"无法定位程序输入点"弹窗;
  - 折叠区提供手动安装命令兜底。
- **一键登录**:弹独立控制台窗口运行 `opencode auth login`(作为备用手段,不是必经步骤)。
- **Key 管理**:`sk-••••••••` 掩码输入 → 「测试连接」→ **只有连通才存进系统钥匙串**;可一键清除。
- **模型选择器**:下拉列出可用模型,标注「· 直连可用」/「🔒 需代理」,附条款小字
  (如"限时免费 · 限速 · 免费期数据或用于训练");选中需代理模型但未配代理时给出明确指引。
- **「帮我选模型」微基准**:每个候选免费模型生成 6 句 → 本地校验器打分 → 排序 → 自动选最高分。
  - 打分权重:JSON 纪律 40% + 校验通过率 40% + 越级惩罚 10% + 延迟 10%(≤5s 满分,≥60s 零分);
  - 未配代理时自动跳过"需代理"模型(直连必失败,评测既浪费额度又拉低体验);
  - 结果连同**名单指纹**存进 `bench` 表,名单变化自动触发重测。
- 界面全程显示模型**友好名**(如 `hy3-free`),不露 `opencode/hy3-free` 这类原始 id。

### 5.4 生成工坊(AI 造句)

两种生成模式共用一套工作台:

#### 模式 A · 按等级生成练习句
输入:场景自由文本(如「下周出差要用的机场句子」)+ 等级 + 句数(10/20/30)。

#### 模式 B · 场景对话(不分等级)
输入:场景描述 + 句数。生成**一段连续的 A/B 真实对话**,产出直接成为「情景对话」页的一个场景包。

#### 共同的运行机制

| 机制 | 说明 |
|---|---|
| **微批** | 总句数拆成微批(桌面端每批 ≤10 句;`channels.json` 的 `default_microbatch` 为策略默认值),逐批请求;进度点 `●●●○○` 实时更新 |
| **流式增量解析** | `StreamScanner` 边收边吐完整 JSON 对象,句卡实时落下,不等整批结束 |
| **活跃信号** | 慢通道上第一批可能跑 1–2 分钟 —— 400ms 节流上报"连接中 / 正在产出(已收 N 字)/ 修补中",外加计时器,界面绝不静止 |
| **逐句校验分诊** | 每句立刻过确定性校验 → ✓ 已入库 / ⟳ 修补中 / ✕ 已丢弃(可展开原因) |
| **修补调用** | 只有 IPA 缺失/非法这类可修问题才发修补请求,**仅传差异**,单次尝试;修不好转"丢弃可捞回" |
| **丢弃可捞回** | 越级 / 重复的句子折叠展示,一键捞回到用户库(捞回同样过精确查重,不产生重复条目) |
| **失败样本回灌** | 本任务中被词表拒绝过的单词,回灌进后续批次 prompt 显式禁用,提高补足批通过率 |
| **拿满机制** | 规划批跑完仍不够用户指定句数 → 自动追加补足批(最多 4 轮,每批多要 50% 余量);**场景模式不补足**(拼接会破坏对话连贯性,实测教训) |
| **精确查重护栏** | simhash 近重之外,入库前再跨出厂库 + 用户库查一次完全同文,保证"每个场景中的句子不重复" |
| **停止 / 续跑** | [停止] 即停表并保留已产出;任务状态存 `gen_queue`,重开应用后 [续跑] 从下一个待办批继续 |
| **限速可视化** | 429 时显示倒计时条,连续 3 次建议切换通道 |
| **预算硬顶** | 付费通道触顶时优雅停止,保留已入库部分 |
| **诚实收尾** | 零产出、停止、补足未遂各有不同的人话总结,并给出可行动建议(换场景 / 提高等级 / 换更日常的说法) |

### 5.5 AI 答疑抽屉

练习解析页的「问 AI」:
- 底部抽屉,**顶部拖拽条可上下调整高度**(记忆到 localStorage);
- 预填模板问题("为什么这里用 __?");
- **打字机流式回答**(60 字/秒),回答用轻量 Markdown 排版(加粗 / 列表 / 行内代码);
- **多轮问答**:同一句内多轮以气泡累积,**近 3 轮**随新问题回传做上下文(限量控 token);
- 切换到下一题自动清空会话;
- 组件常驻挂载,`open` 只控制显隐 —— 关闭再打开不丢当前句的会话;
- 回答限 200 字,`temperature 0.3`。

### 5.6 每周 AI 学习点评

- **只把聚合数字送出去,绝不发送任何句子内容**:本周练习次数、正确次数、连续打卡天数、最薄弱词性及占比。
- 返回 200 字以内的点评 + 三条具体建议,存进 `progress.db` kv。

### 5.7 AI 聊天模块(三模式)

一个导航项承载三种模式,共用 `chat_thread` / `chat_message` 两张表。
**聊天不写 SRS、不记练习日志、不占体验模式限额**;token 用量照常记入 `spend`。

#### 模式一 · 自由聊天
- AI 是"友好耐心的英语陪练":**全英文回复、2–4 短句、先回应再追问**,
  **用词与句长按你的当前等级自适应**(system 里带 `level_descriptor` + 该级 can-do)。
- **话题签冷启动**:点一下即代发(「聊聊我的周末」「介绍我的工作/学习」「最喜欢的食物」)。

#### 模式二 · 角色扮演
- **8 张出厂角色卡**:面试官 💼、咖啡店店员 ☕、酒店前台 🏨、海关官员 🛂、
  房东 🏠、外国朋友 🎉、餐厅服务员 🍽、医生 🩺 —— 每张带英文人设 + **AI 开场白**(建会话即落库,解决冷启动)。
- **自定义角色**:自己写一句人设即可开演。
- AI 全程保持人设、绝不出戏、每句尽量以问题或自然提示收尾;学习者卡壳时给出符合人设的温和提示。
- **情景对话联动**:任一场景包预览页点「和 AI 实战演练」→ 直接新建对应角色扮演会话,AI 即兴演对方。

#### 两个可切换的输出开关(自由聊天 / 角色扮演)

| 开关 | 效果 | 实现 |
|---|---|---|
| **帮我纠错** | AI 在正文后附一张**纠错小卡**:你的原句 → 更好的说法(绿字)+ 一句中文说明为什么 + 🔊 朗读 | 正文后独立一行 `⟦fix⟧{json}` |
| **中文对照** | AI 用一行给出**整段回复的自然中文**,渲染在英文下方(虚线分隔、字号更小,英文仍是主角) | 正文后独立一行 `⟦zh⟧…` |

- 两个标记**顺序不限**,一次请求带回 —— **不额外发一轮,零延迟零加价**。
- **容错原则:绝不丢内容** —— 只有确实解析出标注才切正文;模型没按协议输出(标记缺失 / JSON 坏 / 翻译为空)则整段按纯文本保留。
- **`per_turn` 每轮重申**:opencode 通道用 `-s` 续聊时只发用户消息、system 仅在建会话那次送达,
  所以中途改开关必须把规则随每条消息带上才即时生效;关闭态用**显式禁止**措辞而非省略规则。
- 开关状态记 localStorage,默认都开。

#### 模式三 · 智能体
把本机 opencode CLI 包成一个好用的图形外壳:

- **工作目录显式选择**(系统文件夹选择器);目录不存在 / 被移走时明确报错。
- **建会话时无条件红字安全警告**:实机验证非交互 `run` 模式下,默认智能体的工具
  **不经确认直接执行** —— 因此不提供任何"自动批准"开关,而是把风险如实前置告知。
- **工具活动全程可见**:`⚙ 工具名 · 标题` 状态行实时滚动(running / completed / error)。
- **技能加载单独呈现**:`🧠 技能:名字`。
- **任务清单面板**(对齐 opencode TUI 的 Todo):解析 `todowrite` 事件的完整清单,
  渲染成勾选列表(◉ 进行中高亮 / ☑ 已完成划掉 / ☐ 待办),标题显示 n/m、可折叠;
  **比 TUI 多一点**:清单随消息落库,切走 / 重开仍看得到这轮拆了哪几步。
- **用量计入**:`step_finish` 事件里的 tokens 记入 `spend`。
- **空转 180s 超时**兜底(权限询问挂起 / 断网时不让界面一直转)。
- **删除会话可连带清理工作目录**:确认弹窗勾选后把目录**移入系统回收站**(可找回),
  并层层设防拒绝磁盘根目录 / 用户主目录 / 桌面 / 文档 / 下载 / `C:\Windows` / Program Files /
  应用自身数据目录及其祖先。

#### opencode 原生技能面板(Agent Skills)

- **数据源是 opencode 自己的 `debug skill` 命令** —— 去重、根目录优先级、内置技能全按它的规则来,不另写一套。
- 磁盘上有、却不在该清单里的技能由我们**补扫并标为「未加载」**,尽量说清原因。
- 面板对齐 TUI(搜索框 + ↑↓ 选择 + Enter 使用 + Esc 关闭),并补上 TUI 没有的三件事:
  1. **说明完整显示** + 来源标注(内置 / 全局 · opencode / 全局 · claude / 全局 · agents / 本文件夹 / 上级目录)+ 同名副本 `×N` 折叠;
  2. **手动触发型技能也能用** —— 任何技能(含未加载)可 `⤵` 把正文直接注入这一轮消息(界面仍显示用户原话);
  3. **图形化制作 / 编辑 / 删除** —— 表单生成合规 SKILL.md;改写保留 `name`/`description` 之外的字段,
     并给会炸 YAML 的值自动补引号;删除整目录进回收站。
- **诊断能力**:实测发现 `argument-hint: [稿子] [男声|女声]` 这种写法(YAML 流序列后跟 token)
  会让 **opencode 整份技能拒收**,而 Claude Code 容忍 —— 从 Claude 那边装来的技能因此静默失效。
  面板标出「未加载 + 原因」,**在编辑器里保存一次即自动修复**。
- 另外处理:剥 UTF-8 BOM(PowerShell 写出的文件)、技能名规则校验(小写字母数字 + 单连字符,1–64)。

#### 聊天模块的工程细节

- **每对话单独切模型**(把 opencode 的 `/model` 包成可视化操作):
  顶部模型芯片 → 通道页签 + 模型清单(直连 / 需代理标注)+「跟随设置」回退;
  存 `chat_thread.channel/model/model_label`,下一条消息起生效;
  会话未建时先记住、建完即补;opencode 会话中途换模型仍沿用同一 `-s` 会话,记忆不丢。
- **流式按会话分桶**:`Map<threadId, ThreadStream>`,一个定时器喂所有会话 ——
  多个会话可同时生成,切走再切回来照样看到"正在思考"和已吐出的字;
  侧栏「● 生成中」小圆点;离开整页再回来经 `chat_active_threads` 恢复。
- **停止按会话**:`HashMap<i64, Arc<Notify>>`,[停止] 只掐当前这个,其余会话继续跑;
  被截断的部分回复照常落库并标 `partial`。
- **空回复自愈**:opencode 续聊偶发只回 `step_finish` 不吐 text ——
  检测到空正文时丢掉服务端会话、用本地历史重开一轮(本地 `chat_message` 才是事实源);再空则明确报错。
- **绝不留白**:任何"跑完却没有输出"的情况都给出人话说明 + 可行动建议,不让用户以为卡住。
- **上下文控制**:API 通道回放最近 24 条消息;单会话 500 条上限,超出提示开新话题。
- 聊天空转超时 120s。

## 6. 内容生成管线与确定性校验器

### 6.1 Prompt 装配(`sf-pipeline::prompt`)

刻意拆成**字节稳定的前缀** + **变量尾巴**:
- **前缀(system)**:角色 + `[prompt-version]` + LevelSpec 的 YAML 原样嵌入 + 输出 schema + few-shots + 规则。
  同一等级 / 同一 prompt 版本下逐字节相同 → 免费通道输出更一致,付费通道命中前缀缓存。
- **尾巴(user)**:场景、句数、避重指纹(已接受句的 simhash 16 位指纹)、禁用词表(最多 30 个)。
- **Few-shots**:3 个合格示例(情态疑问句 / 主系表 + 介短 / 特殊疑问句)+ 2 个反例(越级词 / 翻译腔)。
- **场景对话 prompt** 独立一套:**不带 LevelSpec**(不受词表带 / 语法白名单约束),
  改以"真实口语连续对话、A/B 交替、优先高频语块、每句 ≤20 词"为约束,schema 多一个 `speaker` 字段。
- **修补 prompt**:只送句子原文 + 问题列表,要求返回单个 JSON 对象。

### 6.2 流式解析(`sf-pipeline::parse`)

- 在任意包裹文本 / markdown 围栏中定位第一个顶层 JSON 数组(正确处理字符串与转义);
- **逐元素解码** —— 一个坏对象只损失一句,绝不毁整批;
- `StreamScanner` 边收边吐已完整的顶层对象,让工坊实时落卡;
- 修补响应走单对象解析,同样容错。

### 6.3 确定性校验器(`sf-pipeline::validate`)

**零 token 成本**的纯函数检查,分五组、四个严重级:

| 组 | 检查项 | 严重级 |
|---|---|---|
| 结构 | 英文 / 中文非空、有逐词标注 | Fatal |
| 结构 | `en` 分词结果必须与 `words` 数组完全一致 | Fatal |
| 结构 | 词性标签必须落在 **14 个闭合枚举**内 | Fatal |
| 结构 | 成分标签必须落在 **8 个闭合枚举**内 | Fatal |
| 结构 | 成分索引不得越界、不得重叠、**必须覆盖每个词恰好一次** | Fatal |
| 音标 | IPA 字符集白名单校验 | Repairable |
| 音标 | IPA 缺失 | Repairable |
| 音标 | **词典对账覆写**:词面精确命中词典时,以词典 IPA 覆盖模型输出(音标漂移归零) | AutoFixed |
| 等级 | NGSL 词表带越级(专有名词豁免) | Level |
| 等级 | 词表外未知词 | Level |
| 等级 | 句长超出该级 `max_words` | Level |
| 查重 | simhash 近重复(汉明距离 ≤ 16) | Duplicate |

**开放词表模式**:场景对话校验器跳过**全部词表判定**(既不查超带也不查词表外),
其余规则完全不变 —— 真实生活词汇本就不在 NGSL 2827 词内。

每条问题都带**一句话人话原因**(如「「bureaucracy」超出当前等级的常用词范围」),
直接用于工坊 ✕ 徽章的可展开说明。

### 6.4 分诊(`sf-pipeline::triage`)

| 判定 | factory 档(出厂生产) | user 档(生成工坊) |
|---|---|---|
| Pass | 接受 | 接受 |
| NeedsRepair | 发修补调用(仅传差异) | 发修补调用 |
| OverLevel | **改判到合适的等级**(找能同时吸收词带与句长的最小等级) | 丢弃,**可捞回** |
| Duplicate | 丢弃 | 丢弃,**可捞回** |
| Broken | 丢弃 | 丢弃 |

### 6.5 simhash 查重

- 64 位 simhash,基于归一化词 + bigram;
- **阈值 16、bigram 权重 1** —— 按种子句库实测标定:真近重复落在 6–16,
  不同短句最低 17;**宁漏勿错杀**(漏网靠人工抽审兜底)。

## 7. 工厂 CLI(`sf`)与内容生产流水线

`cargo run -p sf-pipeline --features factory --bin sf -- <cmd>`

| 命令 | 作用 |
|---|---|
| `factory validate` | 校验全部种子句 + 定级题库 + 出厂场景包,不写任何文件;任一不过即非零退出 |
| `factory build` | 从种子构建 `content.db`:句子过校验入库、LevelSpec 快照 + `spec_hash`、词典整表、8 个场景包(带 `pack`)、定级题库打进 `meta["placement"]`、内容包 rev |
| `factory gen` | 经任一 AI 通道批量生成句子直接入库(支持 `--channel/--model/--api-key`,代理经 `SF_PROXY`) |
| `gold run` | 金标回归:跑通过率报告,有回归即非零退出(CI 门禁) |
| `export trial` | 导出 Web 试用版内容 JSON(L1–L2 各一节,含 LevelSpec) |
| `export scenario` | 把用户库里某个生成好的场景包导出成出厂 YAML 素材,人工审校后放回 `content/scenario/` |

**场景包内容生产闭环**:工坊生成 → `export scenario` 导出 → 人工审校 → 放进 `content/scenario/` →
`factory build` 强校验入包。8 个出厂包就是这条流水线的产物。

**离线抽审**(`tools/audit/audit_pos.py`):spaCy 对照我方 POS 短码与 universal POS,
输出可疑标注清单供人工抽审;纯 QA 工具,不在任何运行时依赖树里。

## 8. 发行形态:免费版与保留的买断制实现

### 8.0 当前发行形态:免费版(`FREE_EDITION = true`)

`apps/desktop/src-tauri/src/licensing.rs` 顶部的 `FREE_EDITION` 常量决定发行形态,**当前为 `true`**:

- `licensing::current_state()` 直接返回新增的 `LicenseState::Free`,**不读许可证文件、不碰试用锚点**

- `submit_attempt` 的每日额度闸只在 `LicenseState::Lapsed` 时生效 → **永不触发**,句数无上限;
- 顶栏试用胶囊只为 `trial` / `lapsed` 渲染 → **不出现**;
- 设置 · 授权页显示「免费版 · 全部功能已解锁,无需激活、无使用期限」,不再有粘贴激活框。

**装上即全功能,无需激活、无试用倒计时、无每日句数上限。**

下面 8.1 / 8.2 描述的买断制实现**代码原样保留**(`crates/sf-license` + 激活/试用/体验模式全链路,
单测照旧覆盖),把 `FREE_EDITION` 改回 `false` 重新打包即恢复。

### 8.1 离线许可证(`.sflic`,保留实现)

- 格式:JSON 文档 = payload(`v` / `product` / `edition` / `email` / `major_max` / `issued_at`)+ base64 Ed25519 签名。
- **客户端只内嵌公钥**,本地验签,**无激活服务器、不绑设备** —— 换机 = 拷贝 `.sflic` 文件。
- 规范化字节 = `serde_json::to_vec(&payload)`;签发端与验证端共用同一 crate,两侧不可能漂移。
- 版本闸门:`major_max` 覆盖到哪个大版本(买断 + 大版本升级付费)。
- 界面:粘贴激活 → 失败抖动 + 人话原因 / 成功盖章 + 邮箱掩码(`u***@example.com`)+ 一键导出备份。
- **签发 CLI** 在 `issuer` feature 后面(`keygen` / `issue`),**绝不进发行二进制**;每单签发 <10 秒。

### 8.2 试用与体验模式(保留实现,免费版下不生效)

- **14 天全功能试用**,首启写起点。
- **锚点双份持久化**:JSON 文件 + 系统钥匙串,读取时**悲观合并**(取最早起点、最晚观察时钟)——
  删掉其中一份不会重置试用;钥匙串不可用时降级为文件-only(设计如此,不做更深对抗)。
- **时钟回拨即到期**:`now < last_seen` 永久置位;授权页给出无指责性的说明("检测到系统时间曾经回拨…激活后不再受影响")。
- **到期转体验模式**:每日 5 句上限,**不清数据、不弹窗**;顶栏胶囊常驻显示状态并可直达购买。
  额度判定精确到"同一句当天已计过就不重复扣"。

## 9. 数据、隐私与安全

| 事项 | 落地 |
|---|---|
| 学习数据 | 全部存本机 SQLite,不上传 |
| API Key | 只进系统钥匙串(macOS Keychain / Windows 凭据管理器 / Secret Service),内存中为 `SecretString`(drop 时清零),从不打日志 |
| 备份包 | zip 只含 `progress.db` + `user_content.db`,**结构上不含任何密钥**(备份代码没有通往 keystore 的路径) |
| 备份恢复 | **先预览差异**(将合并 N 条较新进度 / M 条练习记录)再确认;重复进度按 `last_at` 保留较新一条 |

## 10. 设计系统、动效与无障碍

### 10.1 设计令牌(`packages/ui/src/tokens.css` —— 色值的唯一存在处)

- **品牌蓝** 8 级(`#2E63E7` 为主色)、**中性灰** 9 级(带 4° 蓝倾向)、语义色四组。
- **语义角色变量**:组件一律使用 `--sf-bg` / `--sf-card` / `--sf-text` 这类变量,主题切换时整体翻转。
- **14 色词性胶囊** + **8 色成分卡片**(底 / 文字 / 描边三值)—— 教学专属色板,禁止挪用作装饰。
- **三套主题**:浅色(默认)/ 深色 `[data-theme="dark"]` 或跟随系统 / **护眼纸色** `[data-theme="paper"]`。
  深色色值由 `scripts/derive-dark-colors.mjs` 从浅色推导,保证对比一致。
- **布局令牌**:`--sf-page-max: 1600px`(列表 / 看板类)、`--sf-page-max-narrow: 1120px`(表单 / 阅读类)、
  `--sf-page-pad: clamp(20px, 2.4vw, 48px)`、`--sf-read-max`。页面不再各自硬编码宽度。

### 10.2 宽屏自适应

- 短内容**改多列而不是拉长条**:句库、工坊生成结果、报告薄弱分析都用
  `auto-fill minmax(440px, 1fr)` 栅格 —— 1920 下 3 列,一屏看完 20 句;
  句库展开解析的那条 `grid-column: 1/-1` 独占整行(成分卡需要宽度)。
- 图表真正自适应:曲线 viewBox 拉伸铺满、热力图按可用宽度决定周数(12–53 周)。
- 热力图是**真日历**:列 = 自然周(周一起始)、行 = 固定星期,带月份标签;
  悬停提示给真实日期(`2026-08-18 周二 · 6 句`)。日索引与后端 `day_index` 同口径
  (本地日),反解时读 UTC 字段 —— 时区偏移已经算进索引里,再解释一次就偏一天。
- 聊天页面板铺满页宽,对话本身收在 920px 列里居中(消息、输入框、技能条共用同一列宽)。
- 实测(打包 exe,1920×1009 与 1008×681 两档):八个页面两侧留白从 378px 降到 118px;
  窄窗口零横向溢出、无横向滚动条。练习 / 情景练习全屏页维持"专注式居中"。

### 10.3 无障碍

- **减少动效**:跟随系统 / 强制开 / 强制关三态;开启时签名时刻直接终态、无撒花。
- **练习区易读排版**开关:加宽字距与词距、关闭连字、字重压到 700。
  (规范原意是换 OpenDyslexic 字体,但字体文件尚未随包 §16.2 —— 开关做的是
  能立即生效的排版手段,标签也如实写明,不谎称字体;woff2 入包后在同一处补
  font-family 即可,开关语义不变。)
- **练习区字号三档**(小 / 中 / 大):只缩放练习区四个字阶,界面字号不动。
- **全局键盘焦点环**:`:where(button, a[href], input, select, textarea, [tabindex])`
  在 `:focus-visible` 时描 2px 主色环;打字板等有意关掉焦点环的地方特异性更高、不受影响。
- 全键盘可达:重组、打字、解析、技能面板均有完整键盘路径。
- **高对比 / 色盲友好尚未实现**:设置结构里有字段,但没有 UI 也没有样式实现(§16.3)。

### 16.5 与规范的有意偏差(已记录在案,非缺陷)

1. token 预估不用 tiktoken-rs —— 四通道无一按 tiktoken 计费,改用保守启发式 + usage 回填。
2. simhash 阈值 16、bigram 权重 1 —— 按种子库实测标定,宁漏勿错杀。
3. `content.db` 无 `note_tpl`/`note_slots` 表 —— note 模板化留在 prompt 侧,库内保留单列。
4. `progress.db` 新增 `favorite` 表 —— 收藏需要落地处;错题本仍由 `srs` 派生。
5. **opencode 只用 standalone `run`,不用 serve/attach** —— 真机证实 1.18.18 的
   `run --attach` 对带密码 serve 只回吐 `step_start`、不转发 text 事件,serve 优先策略不可实现。
6. 周报 PDF = 打印样式 + 系统"另存为 PDF",不引入 PDF 生成依赖。
7. 词表带用 HashMap 而非 fst —— 2800 词条规模下 fst 无收益,接口不变可无痛替换。
8. 重组通过后无独立"mini 签名时刻" —— 重组是入口玩法,撒花仍为打字答对专属。
9. **智能体不提供 `--auto` 开关** —— 实机确认非交互 `run` 下工具本就直接执行,
   与其给一个假的安全开关,不如无条件前置警告。
10. 纠错卡不提供「收藏」—— favorites 指向句库 id,聊天句没有全套标注,
    不做绕过校验管线的半吊子入口。
